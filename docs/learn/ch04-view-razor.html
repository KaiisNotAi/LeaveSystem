1. View 是怎麼被找到的

第 3 章的第 3 條約定： return View() 會去找 Views/{Controller 名}/{Action 名}.cshtml。

先實際撞一次牆。把 LeaveTypesController.Index 改成回傳 View：

修改Controllers/LeaveTypesController.cs
public IActionResult Index()
{
    return View();
}

開 /LeaveTypes，你會看到一個錯誤頁：

錯誤訊息瀏覽器
InvalidOperationException: The view 'Index' was not found.
The following locations were searched:
/Views/LeaveTypes/Index.cshtml
/Views/Shared/Index.cshtml
這是好錯誤 它直接把找過的路徑列出來。以後看到 View 找不到， 先讀這個清單，再去比對你的檔案實際放在哪——通常就是資料夾名稱打錯或少個 s。

照它說的，建立 Views/LeaveTypes/ 資料夾與 Index.cshtml：

新增檔案Views/LeaveTypes/Index.cshtml
@{
    ViewData["Title"] = "假別管理";
}

<h1>假別管理</h1>
<p>這是我的第一個 View。</p>

重新整理，畫面出來了——而且自動套上了跟首頁一樣的導覽列與頁尾。第 4 節會解釋為什麼。

2. Razor 語法速成

.cshtml 就是 HTML，加上一個特殊符號 @： 看到 @，後面就是 C#。

Razor六種你會一直用的寫法
@* 這是 Razor 的註解，不會出現在瀏覽器原始碼裡 *@

@{
    // 大括號區塊：可以寫任意多行 C#（不會輸出東西）
    var today = DateTime.Today;
    var greeting = today.DayOfWeek == DayOfWeek.Monday ? "週一加油" : "你好";
}

@* 1. 輸出一個值 *@
<p>今天是 @today.ToString("yyyy-MM-dd")</p>

@* 2. 輸出複雜運算式要用小括號包起來 *@
<p>明天是 @(today.AddDays(1).ToString("MM/dd"))</p>

@* 3. if 判斷 *@
@if (today.DayOfWeek == DayOfWeek.Sunday)
{
    <p>今天放假</p>
}
else
{
    <p>今天要上課</p>
}

@* 4. 迴圈 *@
@foreach (var n in new[] { "病假", "事假", "公假" })
{
    <span class="badge">@n</span>
}

@* 5. 要輸出一個真正的 @ 符號，打兩次 *@
<p>聯絡信箱：admin@@example.com</p>
最常見的 Razor 錯誤：忘記 @@

在 .cshtml 裡直接寫 Admin@123， Razor 會以為 @123 是 C# 而報一堆奇怪的編譯錯誤。

完成品的登入頁就有這個情況——你去看 Views/Account/Login.cshtml，它寫的是 Admin@@123，畫面上才會正確顯示成 Admin@123。

3. 動手：把資料畫成表格

現在做真正有用的事。先在 Models 建一個假別類別 （這個檔案第 6 章會直接沿用變成資料表）：

新增檔案Models/LeaveType.cs
namespace MyLeaveSystem.Models;

public class LeaveType
{
    public int     Id          { get; set; }
    public string  Name        { get; set; } = string.Empty;
    public string  Code        { get; set; } = string.Empty;
    public bool    IsActive    { get; set; } = true;
    public int     SortOrder   { get; set; }
    public string? Description { get; set; }
}

Controller 造幾筆資料傳給 View：

修改Controllers/LeaveTypesController.cs
using Microsoft.AspNetCore.Mvc;
using MyLeaveSystem.Models;

namespace MyLeaveSystem.Controllers;

public class LeaveTypesController : Controller
{
    public IActionResult Index()
    {
        // 暫時寫死。第 6 章會換成從資料庫讀。
        var types = new List<LeaveType>
        {
            new() { Id = 1, Name = "病假", Code = "SICK",        SortOrder = 1, Description = "因病無法到課" },
            new() { Id = 2, Name = "事假", Code = "PERSONAL",    SortOrder = 2, Description = "個人事務" },
            new() { Id = 3, Name = "喪假", Code = "BEREAVEMENT", SortOrder = 3, Description = "親屬喪事" },
            new() { Id = 4, Name = "公假", Code = "OFFICIAL",    SortOrder = 4, IsActive = false }
        };

        return View(types);      // ← 把資料交給 View
    }
}

View 收下它，畫成表格：

修改Views/LeaveTypes/Index.cshtml
@* 第一行宣告：這個 View 收到的資料是什麼型別 *@
@model List<MyLeaveSystem.Models.LeaveType>

@{
    ViewData["Title"] = "假別管理";
}

<h1>假別管理</h1>
<p class="text-muted">共 @Model.Count 種假別</p>

<table class="table table-striped">
    <thead>
        <tr>
            <th>排序</th><th>名稱</th><th>代碼</th><th>說明</th><th>狀態</th>
        </tr>
    </thead>
    <tbody>
        @foreach (var t in Model.OrderBy(x => x.SortOrder))
        {
            <tr>
                <td>@t.SortOrder</td>
                <td>@t.Name</td>
                <td><code>@t.Code</code></td>
                <td>@(t.Description ?? "—")</td>
                <td>
                    @if (t.IsActive)
                    {
                        <span class="badge bg-success">啟用</span>
                    }
                    else
                    {
                        <span class="badge bg-secondary">停用</span>
                    }
                </td>
            </tr>
        }
    </tbody>
</table>

重新整理 /LeaveTypes——一張有斑馬紋、有狀態徽章的表格。

寫法意思
@model List<…> 小寫 m。宣告這個 View 期待收到什麼型別，一個檔案只能有一行，通常放第一行。
@Model 大寫 M。實際收到的那個物件。因為上面宣告過型別， 所以編輯器有自動完成、打錯會編譯失敗。
@(t.Description ?? "—") 複雜運算式要用小括號包住，Razor 才知道 C# 到哪裡結束。
為什麼強型別 View 很重要

你也可以用弱型別的 ViewBag / ViewData 傳資料， 但那樣打錯屬性名稱要等到執行時才會發現，而且沒有自動完成。

用 @model 的話，把 @t.Nmae 打錯字， 編譯就直接失敗。本書之後一律用強型別。

4. Layout：共用的外框

你剛才那個 View 只寫了 <h1> 和 <table>， 沒有 <html>、<head>、導覽列， 但畫面上卻都有。那些來自 Views/Shared/_Layout.cshtml。

打開它，找到這一行：

RazorViews/Shared/_Layout.cshtml
<main role="main" class="pb-3">
    @RenderBody()      @* ← 你的 View 內容會被塞進這個位置 *@
</main>
Layout 解決什麼問題 沒有 Layout 的話，你的 20 個頁面都要各自寫一份導覽列。 改一個選單項目就要改 20 個檔案，而且一定會漏掉一兩個。 共用的部分寫一次，各頁只寫自己不同的地方。

4.1 動手：在導覽列加一個連結

找到 _Layout.cshtml 裡的導覽列區塊，加一項：

修改Views/Shared/_Layout.cshtml
<li class="nav-item">
    <a class="nav-link text-dark" asp-area="" asp-controller="Home" asp-action="Privacy">Privacy</a>
</li>
<li class="nav-item">
    <a class="nav-link text-dark" asp-area="" asp-controller="LeaveTypes" asp-action="Index">假別管理</a>
</li>

重新整理任何一頁，導覽列都多了「假別管理」。

asp-controller / asp-action 是什麼？為什麼不直接寫 href="/LeaveTypes"？

這叫 Tag Helper。Razor 會在伺服器上把它算成正確的 href，所以最後送到瀏覽器的仍然是普通的 <a href="/LeaveTypes">。

好處是：如果哪天你的網站要部署到子路徑（例如 https://example.com/leave/）， 或者你改了路由樣板，Tag Helper 產生的網址會自動跟著對， 手寫的 href 則會全部壞掉。

這也是為什麼打錯 Controller 名字時不會編譯失敗—— Tag Helper 只是產生字串，不會驗證真的有那個 Controller。連結壞掉要自己點過才知道。

5. 三個底線檔案

檔案作用
Views/_ViewStart.cshtml 每個 View 開始渲染前都會先跑這個。 它的內容通常只有一行 Layout = "_Layout";—— 這就是為什麼你什麼都沒寫，Layout 卻自動套上了。
Views/_ViewImports.cshtml 所有 View 共用的 @using 與 Tag Helper 註冊。 在這裡加 @using MyLeaveSystem.Models， 每個 View 就都不用再寫一次完整命名空間。
Views/Shared/_Layout.cshtml 版面外框本身。

5.1 動手：讓 @model 可以少打字

修改Views/_ViewImports.cshtml
@using MyLeaveSystem
@using MyLeaveSystem.Models
@addTagHelper *, Microsoft.AspNetCore.Mvc.TagHelpers

之後 View 第一行就能簡寫：

修改Views/LeaveTypes/Index.cshtml
@model List<LeaveType>      @* 不用再寫 MyLeaveSystem.Models.LeaveType *@

6. ViewData 與 TempData

@model 是傳「主要資料」的正式管道。 另外有兩個弱型別的口袋，各有各的用途：

活多久典型用途
ViewData[...] 只在這一次渲染有效 頁面標題（你已經在用了：ViewData["Title"]）、下拉選單的選項
TempData[...] 撐過一次轉址，讀取後就消失 「儲存成功！」這類提示訊息

TempData 的存在是因為轉址（Redirect）會產生一個全新的請求， ViewData 撐不過去。第 5 章講 PRG 模式時會實際用到。

C#TempData 的典型用法
// Controller：存好之後轉址
TempData["Success"] = "假別已新增";
return RedirectToAction(nameof(Index));
RazorLayout 或 View 裡顯示
@if (TempData["Success"] != null)
{
    <div class="alert alert-success">@TempData["Success"]</div>
}

7. Razor 幫你擋掉的攻擊

這件事很重要，而且是預設就保護你的，所以很多人不知道它存在。

假設某個假別的說明被人填成：

惡意輸入使用者填進資料庫的內容
<script>alert('你被駭了');</script>

你的 View 寫 @t.Description。 Razor 會自動把它轉義，送到瀏覽器的是：

實際輸出瀏覽器收到的 HTML
&lt;script&gt;alert('你被駭了');&lt;/script&gt;

畫面上會原樣顯示那串文字，而不是執行它。這就擋掉了 XSS 攻擊。

唯一會破功的地方：Html.Raw

@Html.Raw(t.Description) 的意思是「不要轉義，原樣塞進 HTML」。 對使用者輸入的內容用它，等於直接開門讓人執行任意 JavaScript。

規則很簡單：除非你 100% 確定那段 HTML 是你自己產生的，否則永遠不要用 Html.Raw。
