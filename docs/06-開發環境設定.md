第一次拿到專案的人，請依照本文件從零開始把它跑起來。

## 2. SQL Server 設定

### 2.1 確認 SQL Server 已啟動

按 Win 鍵 → 搜尋「SQL Server 組態管理員」→ 確認「SQL Server (MSSQLSERVER)」狀態為「執行中」。

如果是 SQL Server Express，預設執行個體名稱可能是 `SQLEXPRESS`，連線字串要改：
```
Server=.\SQLEXPRESS;...
```

### 2.2 用 SSMS 測試連線

1. 開啟 SSMS
2. 伺服器名稱輸入 `.`（代表本機預設執行個體）或 `.\SQLEXPRESS`
3. 驗證類型選「Windows 驗證」
4. 按連線

如果連得進去，就 OK。

## 3. 修改連線字串（如有需要）

預設連線字串在 `appsettings.json` 與 `appsettings.Development.json`：

```json
"ConnectionStrings": {
  "DefaultConnection": "Server=.;Database=LeaveSystem;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=true"
}
```

| 設定 | 說明 |
|------|------|
| Server=. | 連到本機預設執行個體 |
| Database=LeaveSystem | 資料庫名稱（不存在會由 EF Core 建立） |
| Trusted_Connection=True | 用 Windows 帳號登入 |
| TrustServerCertificate=True | 略過 SSL 憑證驗證（開發機常用） |
| MultipleActiveResultSets=true | 允許同連線多個結果集 |

如果是 SQLEXPRESS，把 `Server=.` 改成 `Server=.\SQLEXPRESS`。

## 4. 建立資料庫（首次 + 每次模型變更後）

### 4.1 安裝 EF Core CLI 工具（只需一次）

```powershell
dotnet tool install --global dotnet-ef
```

如果已安裝過，更新版本：
```powershell
dotnet tool update --global dotnet-ef
```

### 4.2 產生 Migration（每次 Entity 變更後）

```powershell
cd E:\伺服器程式\LeaveSystem
dotnet ef migrations add Init
```

執行後會在 `Migrations/` 資料夾出現一個含時間戳記的 `xxx_Init.cs`，這就是「資料庫變更腳本」。

### 4.3 套用到資料庫

```powershell
dotnet ef database update
```

EF Core 會：
1. 連到 `Server=.`
2. 如果 `LeaveSystem` 資料庫不存在，自動建立
3. 執行 Migration 腳本，建好所有資料表

執行成功後到 SSMS 重新整理「資料庫」節點，就會看到 `LeaveSystem`。

### 4.4 ⚠️ 重要警告：不要直接在 SSMS 改表結構！

EF Core Migration 是「資料庫的版本控制」，每次變更都有歷史。如果你直接在 SSMS：
- 新增欄位
- 修改型別
- 刪除索引

**EF Core 不知道這些變更**，下次 `dotnet ef database update` 時會以為資料庫還是舊版，可能：
- 套用失敗
- 資料遺失
- 錯誤訊息看不懂

**正確做法**：所有 schema 變更都從 Entity 類別出發，再 `dotnet ef migrations add 名稱` 產生新 Migration。

SSMS 的正確用途：
- ✅ 觀察資料表內容（SELECT）
- ✅ 寫查詢測試
- ✅ 備份還原
- ❌ 改 schema（CREATE/ALTER/DROP TABLE）

## 6. Phase 1 完成後的測試帳號

預設管理員：
- 帳號：`Admin`
- 密碼：`Admin@123`

**首次登入後請立刻改密碼**！

之後請用此帳號到「使用者管理」建立其他角色帳號（行政、導師、科長、分署長、學員）。

### 6.1 Phase 1 驗證步驟（執行專案後）

1. 啟動專案後瀏覽器會自動開啟首頁。
2. 因為首頁已加 `[Authorize]`，會被自動導到 `/Account/Login`。
3. 用 `Admin / Admin@123` 登入。
4. 登入後右上角會顯示「您好，系統管理員」與「登出」按鈕。
5. 導覽列會出現「行政後台 → 使用者管理」連結（僅 Admin/Staff 看得到）。
6. 點進「使用者管理」可看到目前唯一的 Admin 帳號。
7. 試著「新增使用者」→ 建立一個導師、科長、分署長、學員，分別測試登入。
8. 用沒有 Admin/Staff 角色的帳號（如學員）登入後直接到 `/Admin/Users`，
   應被導到 `/Account/AccessDenied`（拒絕存取頁）。

確認以上 8 點都通過，Phase 1 即可結案。

## 7. Git 分支策略

### 7.1 主要分支

| 分支 | 用途 |
|------|------|
| `master` | 永遠保持可運作的穩定版 |
| `feature/phaseN-xxx` | 每個 Phase 的工作分支，完成後合併回 master |

### 7.2 開始一個新 Phase

```powershell
git checkout master
git pull
git checkout -b feature/phase2-cohort
```

### 7.3 工作中

```powershell
# 每完成一個邏輯里程碑就 commit
git add .
git commit -m "feat(phase2): 班期 CRUD 控制器"
```

### 7.4 完成 Phase

```powershell
# 1. push 工作分支（保留歷史）
git push -u origin feature/phase2-cohort

# 2. 切回 master 並合併
git checkout master
git merge --no-ff feature/phase2-cohort -m "Merge Phase 2：班期管理"

# 3. 打 tag
git tag -a v0.3-phase2 -m "Phase 2 完成：班期 CRUD"

# 4. push 到 GitHub
git push origin master --tags
```

### 7.5 Commit Message 慣例

| 前綴 | 用途 |
|------|------|
| `feat:` | 新功能 |
| `fix:` | 修 Bug |
| `docs:` | 改文件 |
| `refactor:` | 重構（不改行為） |
| `chore:` | 雜項（套件升級、設定） |
| `test:` | 加/改測試 |

範例：
```
feat(phase3): 學員提交請假表單
fix: 修正時數計算遇午休錯誤
docs: 更新資料模型文件
```

## 8. 換電腦／新成員第一次設定

如果您今天換了一台電腦，或要把專案分享給新加入的成員，請依照以下步驟：

### 8.1 必要軟體

請見 §1 必要軟體清單，缺一不可。VS 2026 安裝時記得勾「ASP.NET 與網頁開發」工作負載，這樣才會自動帶 .NET 10 SDK。

### 8.2 設定 Git 身分（每台電腦只需一次）

```powershell
git config --global user.name "您的名稱"
git config --global user.email "您的Email"
```

注意是 `--global`，這樣這台電腦上所有 repo 都會用同一組身分，不必每個 repo 重設。

### 8.3 設定 GitHub 認證（推送/拉取時用）

GitHub 已不接受密碼登入，請從以下兩種方式擇一：

**方式 A（推薦）：用 GitHub CLI**
```powershell
winget install --id GitHub.cli
gh auth login
```
依序選 `GitHub.com` → `HTTPS` → `Login with a web browser`，完成後 git 推送會自動使用此認證。

**方式 B：用 Personal Access Token（PAT）**
1. 到 [github.com/settings/tokens](https://github.com/settings/tokens) 建立 Classic Token，勾 `repo` 權限。
2. 第一次 `git push` 時，帳號輸入您的 GitHub 名稱、密碼貼上 Token。Windows 認證管理員會記住，之後不必再輸入。

### 8.4 補上 NuGet 來源（避免套件還原失敗）

新電腦預設可能缺 nuget.org 來源，先檢查：

```powershell
dotnet nuget list source
```

若沒有 `https://api.nuget.org/v3/index.json`，補上：

```powershell
dotnet nuget add source "https://api.nuget.org/v3/index.json" --name "nuget.org"
```

### 8.5 Clone 專案

選一個位置（例如 `E:\伺服器程式`）：

```powershell
cd E:\伺服器程式
git clone https://github.com/KaiisNotAi/LeaveSystem.git
cd LeaveSystem
```

> 第一次抓下來叫 `git clone`；之後在這個資料夾裡更新才叫 `git pull`。

### 8.6 還原套件 + 建置

```powershell
dotnet restore
dotnet build
```

若這步成功，就代表程式碼端 OK。若有 NuGet 找不到的錯誤，回到 §8.4 確認。

### 8.7 確認 SQL Server 設定

```powershell
sqlcmd -S . -E -Q "SELECT @@VERSION;"
```

跑得出 SQL Server 版本字串就 OK。
若您裝的是 SQL Express，預設執行個體名稱通常是 `SQLEXPRESS`，記得修改 `appsettings.json` 與 `appsettings.Development.json` 的連線字串：

```json
"Server=.\\SQLEXPRESS;Database=LeaveSystem;..."
```

注意 JSON 裡反斜線要寫兩個 `\\`。

### 8.8 F5 啟動

第一次跑：
1. `EnsureCreated()` 自動建好 `LeaveSystem` 資料庫
2. `SeedData` 寫入 6 角色 + Admin 帳號 + 4 假別 + 3 規則
3. 自動開瀏覽器 → 用 `Admin / Admin@123` 登入

### 8.9 兩台電腦交替工作的注意事項

如果您會在多台電腦同時開發，最重要的一條規則：

> **離開某台電腦前，一定要 `git push` 把工作分支推上 GitHub。**

| 動作 | 指令 |
|------|------|
| 離開 A 電腦前（即使工作沒做完）| `git add . ; git commit -m "wip" ; git push` |
| 到 B 電腦繼續開發 | `git fetch ; git checkout feature/xxx ; git pull` |
| 改完繼續 | `git push` |

> 「wip」是 work in progress 的縮寫，代表「進行中的工作」。
> 之後 Phase 結束要 merge 回 master 前，可以用 `git rebase -i` 把 wip 提交合併整理。

### 8.10 換電腦快速 checklist

新電腦第一次設定（一次性）：
- [ ] 裝 VS 2026 + SQL Server + SSMS + Git
- [ ] `git config --global user.name/user.email`
- [ ] GitHub 認證（`gh auth login` 或 PAT）
- [ ] `dotnet nuget add source` 補 nuget.org
- [ ] `git clone` 專案
- [ ] `dotnet restore && dotnet build`
- [ ] 修改連線字串（如需要）
- [ ] F5 跑起來，用 Admin/Admin@123 登入

每次開工：
- [ ] `git pull` 拉最新
- [ ] `git checkout -b feature/...` 新分支
- [ ] 寫程式
- [ ] `git commit && git push`

換電腦前：
- [ ] `git push` 所有變更（包含未完成的 wip）

## 9. 常見問題排除

### Q：dotnet ef 指令找不到？
→ 安裝 EF Core CLI：`dotnet tool install --global dotnet-ef`

### Q：連線字串錯誤、找不到伺服器？
→ 確認 SQL Server Service 在跑；確認 `Server=.` 或 `.\SQLEXPRESS` 對應您的安裝。

### Q：build 時 NuGet 套件還原失敗？
→ 檢查 `dotnet nuget list source`，確認包含 `https://api.nuget.org/v3/index.json`。
   若沒有：`dotnet nuget add source https://api.nuget.org/v3/index.json --name nuget.org`

### Q：F5 後 IIS Express 拋例外？
→ 第一次跑可能要安裝開發用 SSL 憑證：`dotnet dev-certs https --trust`
