### Day 2 — 模組 D 第 3~5 站（BCrypt → Claims → Cookie）

**做了什麼：**

- [x] 第 3 站：BCrypt 密碼比對（拆解雜湊字串、實驗 Verify）
- [x] 第 4 站：建立 ClaimsPrincipal（看 Claims 陣列一筆筆長出來）
- [x] 第 5 站：寫入 Cookie（觀察瀏覽器 F12 拿到的加密 Cookie）
- [x] 觀察「回程」：Cookie 帶回時 `User` 是怎麼還原的

**觀察到的事：**

- BCrypt 雜湊字串格式：`$2a$11$Salt(22字元)Hash(31字元)`
  - `$2a$` = 演算法版本
  - `$11$` = Work factor（2¹¹ 次迴圈，數字越大越慢越安全）
  - Salt 就明文寫在裡面 → 不是漏洞，是設計
- 同一個密碼 Hash 兩次結果**不同**（Salt 隨機），但 Verify 都會通過
- Verify 過程：從雜湊字串抽出 Salt → 用相同 Salt 重算 → 比對
- Claims 陣列：4 筆
  - `NameIdentifier` = "1"
  - `Name` = "系統管理員"
  - `Username` = "Admin"（自訂 Type）
  - `Role` = "Admin"
- **ClaimsIdentity 一定要指定 AuthenticationType**（"Cookies"），否則 `IsAuthenticated = false`
- 瀏覽器 F12 → Application → Cookies 看到的 `LeaveSystem.Auth` 是**加密亂碼**
- `document.cookie` 讀不到（因為 HttpOnly）→ 防 XSS 偷 Cookie
- 登入後任何 Controller 都能用 `User.Identity.Name`、`User.IsInRole("Admin")`、`User.FindFirst(ClaimTypes.NameIdentifier)?.Value`

**新學到的概念：**

- **Claim / ClaimsIdentity / ClaimsPrincipal 三層**：Claim=一行資訊、Identity=一組來自同來源的 Claims、Principal=完整使用者（皮夾裡可以有多張證件）
- **Data Protection API**：ASP.NET Core 內建加密，Cookie 內容用它加密簽章
- **UseAuthentication 必須在 UseAuthorization 之前**：先知道你是誰，才能判斷你能不能做
- **IsPersistent**：false = Session Cookie（關瀏覽器沒了）；true = 寫進硬碟到 ExpiresUtc 才過期

**卡關解決：**

- BCrypt Work Factor 12 vs 10 → 每 +1 時間翻倍，這就是「攻擊者破解成本翻倍」

### Day 4 — EF Core Migration 遷移

**做了什麼：**
- [x] 把 EnsureCreated() 換成 Migrate()
- [x] 產第一個 Migration：InitialCreate
- [x] 完全理解「Migration 是資料庫的版本控制」概念

**新學到的概念：**
- `dotnet ef migrations add XxxName` = 產出「這次的變更腳本」
- `dotnet ef database update` = 執行未套用的腳本
- `__EFMigrationsHistory` 表 = 記錄「哪些 Migration 已跑過」
- `Migrate()` 開機時自動同步，兩台電腦零手動

**遇到的坑：**
- Migration 產出前一定要先確認 dotnet-ef CLI 有裝
- Migration 產完 → 資料庫要先 drop（如果之前是 EnsureCreated 建的）
- 不要用 SSMS 直接改 schema，會讓 Migration 混亂

### 一個 HTTP 請求的生命週期（簡化版）

```
[瀏覽器發 HTTP 請求]
		↓
Program.cs 中介軟體管線
  UseRouting        → 解析 URL 對應到哪個 Controller
  UseAuthentication → 從 Cookie 還原 ClaimsPrincipal
  UseAuthorization  → 檢查 [Authorize] 等規則
		↓
Controller Action 執行
		↓
回傳 View / JSON / Redirect
		↓
[瀏覽器顯示結果]
```

### BCrypt 雜湊字串拆解

```
$2a$11$NmrQCP...(22字元)...abcdefg1234
 ↑   ↑     ↑                  ↑
 版  Work  Salt (隨機)        雜湊本體 (Salt+密碼算出來)
 本  factor                   
	 (2¹¹ 迴圈)
```

- **Salt 明文寫在雜湊裡** → 這不是漏洞，是設計
- Salt 目的是「讓相同密碼變成不同雜湊」，防彩虹表
- Verify 從雜湊字串抽 Salt → 用相同 Salt 重算 → 比對

### Claims 三層心智模型

```
🎫 ClaimsPrincipal (皮夾)
   ├── 📇 ClaimsIdentity #1 (身分證，AuthenticationType="Cookies")
   │    ├── Claim: NameIdentifier = "1"
   │    ├── Claim: Name = "系統管理員"
   │    ├── Claim: Username = "Admin"
   │    └── Claim: Role = "Admin"
   │
   └── 📱 ClaimsIdentity #2 (可能還有其他身分，我們現在只用一個)
```

| 概念 | 對應 |
|------|------|
| **Claim** | 一張證件上的**一行資訊** |
| **ClaimsIdentity** | 一張**證件**（同來源的一組 Claims）|
| **ClaimsPrincipal** | 一個**皮夾**（可能有多張證件）|

### Controller 常用取當前使用者資訊

```csharp
User.Identity.IsAuthenticated                          // 是否已登入
User.Identity.Name                                     // 顯示名稱
User.IsInRole("Admin")                                 // 是否為某角色
User.FindFirst(ClaimTypes.NameIdentifier)?.Value       // 使用者 ID (string)
```

### LINQ 常用方法
