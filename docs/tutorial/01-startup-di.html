Flow 01 · Startup & Dependency Injection

啟動與 DI 生命週期

按下 F5 之後、第一個 HTTP 請求進來之前，Program.cs 做完了三件事： ① 把所有服務登記到 DI 容器、 ② 把資料庫結構同步到最新並補上種子資料、 ③ 依固定順序組出中介軟體管線。 這三件事的順序寫錯，後面每一條流程都會壞。

循序圖

主機 組裝進入點 DI 容器 EF Core 資料庫 實線＝呼叫，虛線＝回傳

3 AddDbContext<AppDbContext>(o => o.UseSqlServer(cs)) Program.cs:32

連線字串從 ConnectionStrings:DefaultConnection 讀。 AddDbContext 預設是 Scoped：一個 HTTP 請求一個 DbContext 實例， 所以同一次請求裡 Controller 與 Service 拿到的是同一個追蹤上下文。 

builder.Services.AddDbContext<AppDbContext>(options =>
{
    var connectionString = builder.Configuration.GetConnectionString("DefaultConnection")
        ?? throw new InvalidOperationException("找不到連線字串 DefaultConnection…");
    options.UseSqlServer(connectionString);
});

7 scope.ServiceProvider.GetRequiredService<AppDbContext>() Program.cs:87–89

AppDbContext 是 Scoped，而啟動當下還沒有任何 HTTP 請求， 因此必須自己 CreateScope() 開一個範圍才拿得到；用完隨 using 釋放。

}

public static void Initialize(AppDbContext db)
{

11 UseRouting → UseAuthentication → UseAuthorization Program.cs:119–123

中介軟體是依註冊順序串成一條管線，每個請求照順序穿過。 這三個的順序不能換：先知道「要去哪個 Action」，才知道「這個 Action 需不需要登入」； 先算出「你是誰」（Authentication），才能判斷「你能不能」（Authorization）。 

app.UseRouting();
app.UseAuthentication();   // 讀 Cookie → 還原 ClaimsPrincipal（你是誰）
app.UseAuthorization();    // 比對 [Authorize(Roles=…)]（你能不能）
順序寫反會怎樣
把 UseAuthorization() 放到 UseAuthentication() 前面， 授權階段拿到的 User 會是空的匿名身分， 所有掛 [Authorize] 的頁面都會變成永遠拒絕，而且不會有編譯錯誤。
12 MapControllerRoute(…) · app.Run() Program.cs:127–132

註冊預設路由樣板 {controller=Home}/{action=Index}/{id?}， 然後 app.Run() 開始監聽。從這一刻起， 後面七張圖描述的流程才會開始被觸發。 

app.MapControllerRoute(
    name: "default",
    pattern: "{controller=Home}/{action=Index}/{id?}")
    .WithStaticAssets();

app.Run();

關鍵設計決策

決策為什麼
服務一律用 AddScoped Service 內部都持有 AppDbContext；若註冊成 Singleton， 會把一個 Scoped 的 DbContext 抓成長生命週期物件，導致跨請求共用追蹤狀態而爆炸。
啟動時就 Migrate() 這是教學／單機專案的取捨：換來「pull 完 F5 就能跑」。 正式多節點部署時會改成部署腳本執行 dotnet ef database update， 避免多個執行個體同時搶著 migrate。
種子資料寫在程式而非 SQL 腳本 密碼要經過 BCrypt 雜湊，SQL 腳本寫不出來；而且可以用 Any() 做冪等判斷。

自己動手驗證

  1. 在 Program.cs:97（db.Database.Migrate()）設中斷點，F5，觀察它在第一個請求進來之前就停住。
  2. 把 appsettings.json 的 Database=LeaveSystem 改成一個不存在的名字再 F5， 看它自動把整個資料庫建起來，然後改回去。
  3. 把 app.UseAuthentication() 與 app.UseAuthorization() 對調， 登入後開任何頁面都會被踢回登入頁——親眼看過一次就不會忘記順序。記得改回來。
  4. 把 AddScoped<IApprovalService, ApprovalService>() 註解掉， 開 /Approvals，看它丟出 Unable to resolve service for type…—— 這就是 DI 沒登記的長相。
