1. 先弄一個能亂試的地方

讀語法最快的方式是邊讀邊跑。開一個終端機，建一個丟完就刪的小專案：

終端機找個空資料夾執行
dotnet new console -o CsPlayground
cd CsPlayground
dotnet run

它會印出 Hello, World!。之後你把本章的範例貼進 Program.cs， 存檔後再 dotnet run 一次就看得到結果。

印東西出來看 Console.WriteLine(x); 是你這一章最好的朋友。 看不懂某個值是什麼，就印出來。

2. 變數與型別

C# 是強型別語言：每個變數都有固定的型別，宣告之後不能改放別種東西。

C#基本型別
int      hours    = 8;                 // 整數
decimal  total    = 4.5m;              // 精確小數（注意結尾的 m）
string   name     = "王小明";          // 文字
bool     isActive = true;              // 真 / 假
DateTime startAt  = new DateTime(2026, 9, 15, 8, 0, 0);   // 日期時間

// var = 「型別你自己看右邊推」，右邊是什麼型別，左邊就是什麼型別
var hours2 = 8;          // 這就是 int，不是「動態型別」
var name2  = "王小明";   // 這就是 string
為什麼時數要用 decimal 不用 double？

double 是「浮點數」，用二進位近似小數， 0.1 + 0.2 會得到 0.30000000000000004。 拿來算錢或算時數，累加久了就會對不起來。

decimal 用十進位存，不會有這種誤差，代價是慢一點、佔記憶體多一點。 涉及金額、時數這類「數字必須精確」的場合一律用 decimal。 完成品專案裡 LeaveRequest.TotalHours、AbsenceRecord.Hours 都是 decimal，就是這個原因。

3. null：C# 最重要的一件事

null 代表「這裡沒有東西」。它是所有新手 bug 的最大來源， 所以現代 C# 專案都會打開一個叫做 可為 Null 參考型別 的檢查。 你在 .csproj 裡看到的這一行就是它：

XML任何一個現代 .NET 專案的 .csproj
<Nullable>enable</Nullable>

打開之後，型別後面加不加問號的意思完全不同：

C#有沒有問號差很多
string  name  = "王小明";   // 保證不會是 null，可以直接用
string? email = null;      // 可能是 null，用之前要檢查

// 編譯器會對這行發出警告：email 可能是 null
Console.WriteLine(email.Length);

// 正確做法一：先檢查
if (email is not null)
{
    Console.WriteLine(email.Length);
}

// 正確做法二：?. 「如果是 null 就整串當 null，不要爆炸」
Console.WriteLine(email?.Length);       // email 是 null → 印出空白，不會出錯

// 正確做法三：?? 「如果左邊是 null，就用右邊這個預設值」
string shown = email ?? "（未填）";
你一定會遇到：NullReferenceException

執行時跳出 System.NullReferenceException: Object reference not set to an instance of an object. 就是「你對一個 null 呼叫了東西」。

訊息裡會告訴你是哪一行。到那一行去看：那一行有幾個 .，就有幾個嫌疑犯。 例如 request.Student.Cohort.Name 這行爆掉， 可能是 Student 是 null，也可能是 Cohort 是 null。 這在第 8 章講到「關聯資料忘記 Include」時會非常常見。

4. class 與屬性

class 是「一種東西的設計圖」。 以下是完成品專案裡真正的 LeaveType（假別）類別，去掉註解後的樣子：

C#取自完成品：Models/Entities/LeaveType.cs
public class LeaveType
{
    public int     Id          { get; set; }
    public string  Name        { get; set; } = string.Empty;
    public string  Code        { get; set; } = string.Empty;
    public bool    IsActive    { get; set; } = true;
    public int     SortOrder   { get; set; }
    public string? Description { get; set; }
}

逐項拆解：

寫法意思
public外面的程式碼可以存取。相對的 private 只有這個 class 內部能用。
{ get; set; }這叫屬性。可以讀（get）也可以寫（set）。 你可以先粗略理解成「一個欄位」。
= string.Empty;預設值。沒寫的話 string 預設是 null， 打開 Nullable 檢查後編譯器會念你，所以給個空字串。
string?這個欄位允許是 null（描述可以不填）。

用它建立一個實體：

C#物件初始化語法
var sick = new LeaveType
{
    Name = "病假",
    Code = "SICK",
    SortOrder = 1,
    Description = "因病無法到課"
};

Console.WriteLine(sick.Name);        // 病假
Console.WriteLine(sick.IsActive);    // True（用了預設值）

4.1 計算屬性：只有 get 沒有 set

有些值不需要存起來，用算的就好。完成品專案的 Cohort（班期）就有一個：

C#取自完成品：Models/Entities/Cohort.cs
public int TotalHours        { get; set; }   // 總上課時數，例如 900
public int LeaveLimitPercent { get; set; } = 10;  // 上限百分比

// 請假上限 = 總時數 × 百分比，無條件捨去。這個值不存資料庫，每次用到才算。
public int LeaveLimitHours => (int)Math.Floor(TotalHours * LeaveLimitPercent / 100.0);
為什麼上限要用算的，不存一個欄位？ 因為存起來就會有兩份真相。如果行政把 TotalHours 從 900 改成 800， 卻忘了同步更新那個上限欄位，系統就會拿舊的上限去擋人。 用算的則永遠一致。這叫「單一真相來源」。

5. enum：一組固定的選項

當某個欄位只可能是幾個固定值之一時（例如請假單的狀態），用 enum 比用字串安全： 打錯字編譯就會失敗，而不是等到執行時才發現。

C#取自完成品：Models/Enums/LeaveStatus.cs
public enum LeaveStatus
{
    Draft     = 0,   // 草稿
    Pending   = 1,   // 簽核中
    Approved  = 2,   // 已核准
    Rejected  = 3,   // 已駁回
    Cancelled = 4    // 已取消
}

// 用起來
var status = LeaveStatus.Pending;
if (status == LeaveStatus.Approved) { /* … */ }
數字要自己指定 不寫 = 0, = 1 的話 C# 會自動從 0 編號。 但這些數字會直接存進資料庫，所以一定要明確寫出來—— 將來有人在中間插一個新狀態，順序一亂，資料庫裡的舊資料就全部變成別的意思了。

6. 集合與 LINQ

List<T> 是「一串同型別的東西」。<T> 裡填元素的型別。

C#List 基本操作
var types = new List<LeaveType>
{
    new LeaveType { Name = "病假", Code = "SICK",        SortOrder = 1 },
    new LeaveType { Name = "事假", Code = "PERSONAL",    SortOrder = 2, IsActive = false },
    new LeaveType { Name = "公假", Code = "OFFICIAL",    SortOrder = 4 }
};

Console.WriteLine(types.Count);     // 3
Console.WriteLine(types[0].Name);   // 病假（從 0 開始數）

foreach (var t in types)
{
    Console.WriteLine(t.Name);
}

6.1 LINQ：對集合下查詢

LINQ 讓你用接近描述目的的方式操作集合，而不是自己寫迴圈。 這幾個是本書會一直用到的：

C#六個一定要會的 LINQ 方法
// Where：篩選出符合條件的
var active = types.Where(t => t.IsActive).ToList();

// OrderBy：排序（OrderByDescending 是反過來）
var sorted = types.OrderBy(t => t.SortOrder).ToList();

// Select：把每個元素轉成別的東西
var names = types.Select(t => t.Name).ToList();     // List<string>

// FirstOrDefault：找第一個符合的，找不到回 null（First 找不到會丟例外）
var sick = types.FirstOrDefault(t => t.Code == "SICK");

// Any：有沒有任何一個符合？回 true / false
bool hasInactive = types.Any(t => !t.IsActive);      // true

// Sum：加總
int orderTotal = types.Sum(t => t.SortOrder);        // 1 + 2 + 4 = 7

6.2 t => t.IsActive 這是什麼？

這叫 Lambda 運算式，是「一個沒有名字的小函式」。 => 唸作「goes to」，左邊是參數，右邊是回傳的東西。

C#Lambda 的三種等價寫法
// 這三行意思完全一樣：「給我一個 t，我回傳 t.IsActive」
t => t.IsActive
(LeaveType t) => t.IsActive
delegate (LeaveType t) { return t.IsActive; }

// 所以 Where(t => t.IsActive) 讀作：
// 「篩出那些『把它叫做 t 時，t.IsActive 為 true』的元素」

// 參數名字隨你取，這樣寫完全一樣：
types.Where(x => x.IsActive)
types.Where(假別 => 假別.IsActive)

6.3 GroupBy：分組統計

這個稍微難一點，但報表章節（第 12 章）會用到，先看過有印象就好：

C#改寫自完成品：Services/LeaveReportService.cs
// 把一堆請假單，依「假別」分組，算出每種假別請了幾小時、幾張單
var summary = approved
    .GroupBy(r => r.LeaveTypeName)              // 依假別名稱分組
    .Select(g => new
    {
        LeaveTypeName = g.Key,                  // g.Key 就是分組的依據（假別名稱）
        TotalHours    = g.Sum(r => r.Hours),    // g 是這一組裡的所有元素
        Count         = g.Count()
    })
    .ToList();

// 結果類似：
//   病假  8.00 小時  1 張
//   事假 16.00 小時  1 張
為什麼幾乎每次結尾都有 .ToList()？ LINQ 是延遲執行的：Where(...) 本身不會馬上算， 它只是記下「等一下要這樣篩」。.ToList() 才真的跑一遍並產出結果。 這在第 6 章講 EF Core 時很關鍵——沒 ToList() 之前，查詢還沒送到資料庫。

7. 介面：為什麼要多此一舉

interface 是一份「約定」：規定「誰想當這種東西，就必須提供這些方法」， 但完全不管方法內容怎麼寫。

C#取自完成品：Services/ILeaveCalculator.cs（介面）
public interface ILeaveCalculator
{
    // 只有簽章，沒有內容，也沒有 public（介面成員本來就是公開的）
    bool TryCalculate(DateTime startAt, DateTime endAt,
                      out decimal totalHours, out string? errorMessage);
}
C#取自完成品：Services/LeaveCalculator.cs（實作）
// 「: ILeaveCalculator」＝ 我遵守這份約定
public class LeaveCalculator : ILeaveCalculator
{
    public bool TryCalculate(DateTime startAt, DateTime endAt,
                            out decimal totalHours, out string? errorMessage)
    {
        // …真正的計算邏輯在這裡…
    }
}
明明只有一個實作，為什麼要多寫一個介面？

兩個理由，都很實際：

① 測試。第 9 章你會寫測試。假設要測「請假單送出流程」， 但它會發 Email。測試時你不想真的寄信，就換一個「假的 Email 寄送器」塞進去。 因為程式只認介面 IEmailSender，換實作不用改任何一行 Controller。

② 分工。介面先訂好，寫 Controller 的人和寫 Service 的人可以同時開工， 不用等對方寫完。

習慣上介面名稱前面加 I（Interface）。你在完成品專案看到的 IAuthService、IApprovalService、ILeaveReportService 都是介面。

7.1 out 參數

TryCalculate 用到了 out。它的意思是「這個參數是我回傳給你的，不是你給我的」。 一個方法只能 return 一個值，out 讓你多帶幾個出來：

C#out 的用法
var calculator = new LeaveCalculator();

// out var 就地宣告變數接住回傳值
if (calculator.TryCalculate(startAt, endAt, out var hours, out var error))
{
    Console.WriteLine($"共 {hours} 小時");     // 成功：hours 有值
}
else
{
    Console.WriteLine(error);                // 失敗：error 說明為什麼
}
為什麼不直接丟例外就好？ 「使用者填錯時段」是預期內會發生的事，不是程式出錯。 例外（Exception）應該留給真正意外的狀況。 TryXxx 這種「回傳 bool + out 錯誤訊息」的寫法， 讓呼叫端可以直接把訊息顯示給使用者，不用寫 try/catch。 C# 內建的 int.TryParse 也是同一個模式。

8. async / await

本書幾乎每一個跟資料庫有關的方法都長這樣：

C#async 方法的標準長相
public async Task<IActionResult> Index()
{
    var items = await _db.LeaveTypes.ToListAsync();
    return View(items);
}
元素意思
async宣告「這個方法裡面會有 await」。
Task<T>回傳型別要包一層。 「一個將來會給你 T 的承諾」。沒有回傳值的話就寫 Task。
await「等這件事做完，再繼續往下」。 寫了 await 之後，Task<T> 就變回你要的 T。
方法名尾巴 Async純粹是慣例，提醒呼叫的人要 await。
為什麼要這麼麻煩？直接等不行嗎？

查資料庫要花時間（可能幾十毫秒）。這段時間如果整條執行緒傻等， 那條執行緒就不能服務別的使用者。

await 的意思是：「我要等資料庫，這段期間把執行緒還回去服務別人， 資料回來了再叫我繼續。」同樣的伺服器，能同時服務的人多很多。

新手記住規則就好：看到方法名結尾是 Async，前面就要加 await； 用了 await，方法自己就要標 async 並把回傳型別包成 Task<…>。

常見錯誤：忘記 await

寫 var items = _db.LeaveTypes.ToListAsync();（漏了 await）， items 的型別會是 Task<List<LeaveType>> 而不是 List<LeaveType>， 接著你想 items.Count 就會編譯失敗，訊息類似：

'Task<List<LeaveType>>' 未包含 'Count' 的定義

看到訊息裡出現 Task<，第一個念頭就是「我是不是漏了 await」。

9. 其他你會一直看到的寫法

9.1 字串插值 $"…"

C#把變數塞進字串
var name = "王小明";
var hours = 4.5m;

// 前面加 $，就可以在字串裡用 { } 放變數
Console.WriteLine($"學員 {name} 請了 {hours} 小時");
// → 學員 王小明 請了 4.5 小時

// 冒號後面是格式：0.## 代表最多兩位小數、尾巴的 0 不顯示
Console.WriteLine($"共 {hours:0.##} 小時");        // 共 4.5 小時
Console.WriteLine($"{DateTime.Today:yyyy-MM-dd}");  // 2026-08-19

9.4 靜態成員 static

static 表示「這個東西屬於類別本身，不屬於任何一個實體」。 不用 new 就能直接用：

C#static 的例子
Math.Floor(8.7)          // 不用 new Math()
DateTime.UtcNow          // 不用 new DateTime()
string.IsNullOrWhiteSpace(x)

// 自己寫的話：純計算、不依賴任何實體狀態的方法，就適合 static
private static bool IsOnTheHour(DateTime dt)
{
    return dt.Minute == 0 && dt.Second == 0;
}
