# 05 — 開發階段與里程碑

## 整體規劃

本系統採「**整體規劃 + 分階段實作**」方式：每個 Phase 完成後驗證可用，再進下一個 Phase。

## Git 分支策略

- 主分支：`master`
- 每個 Phase 開 `feature/phaseN-xxx` 分支
- 完成驗證後 `git merge --no-ff` 回 master，並打 tag

## Phase 進度

## Phase 6：曠課紀錄 ✅ 已完成（tag `v0.7-phase6`）

**目標**：行政可登錄曠課；學員可查閱。

**交付物**：
- `AbsenceRecord` 時數規則調整為 1~100 小時，最小單位 1 小時
- `AbsenceRecordViewModels`（行政新增/編輯/查詢、學員自查）
- `IAbsenceRecordService` / `AbsenceRecordService`
- 行政端 `Admin/AbsenceRecordsController + Views`（列表篩選、新增、編輯、刪除）
- 學員端 `AbsenceRecordsController + Views`（日期篩選、本人紀錄、累計曠課時數）
- `_Layout` 導覽列入口（行政：曠課紀錄管理；學員：我的曠課紀錄）
- `AbsenceRecordServiceTests` 與 `AbsenceRecordTestScenario`

**驗證**：
1. 行政可依班期 / 學員 / 日期區間查詢曠課紀錄，並看到篩選後總時數
2. 行政可新增、編輯、刪除曠課紀錄，且只能選擇 Student 角色使用者
3. 曠課時數只接受 1~100 的正整數，不接受 0.5 / 1.5 等小數
4. 學員只能查閱自己的曠課紀錄，且累計曠課時數不受日期篩選影響
5. 學員端與行政端 `AbsenceRecords` 同名 Controller 的 View 路徑已明確分流，避免 Admin View 優先命中造成模型型別錯誤

**目前進度（2026-07）**：
- ✅ 已完成：Service Layer + TDD 規格測試（14 條曠課核心規則）
- ✅ 已完成：行政端 `/Admin/AbsenceRecords` CRUD 與查詢頁
