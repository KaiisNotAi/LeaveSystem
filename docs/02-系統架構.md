# 02 — 系統架構

## 1. 整體架構（分層）

```
┌──────────────────────────────────────────────────────────┐
│  Browser（瀏覽器）                                        │
│   - 學員 / 導師 / 科長 / 分署長 / 行政 / 管理員           │
└──────────────────────────┬───────────────────────────────┘
						   │  HTTPS
						   ▼
┌──────────────────────────────────────────────────────────┐
│  ASP.NET Core 中介軟體管線                                │
│   UseRouting → UseAuthentication → UseAuthorization      │
└──────────────────────────┬───────────────────────────────┘
						   ▼
┌──────────────────────────────────────────────────────────┐
│  Controllers（呈現層）                                    │
│   - 接收 HTTP 請求、做模型驗證                            │
│   - 不寫商業邏輯，呼叫 Services                            │
│   - 回傳 View 或 RedirectToAction                         │
└──────────────────────────┬───────────────────────────────┘
						   ▼
┌──────────────────────────────────────────────────────────┐
│  Services（商業邏輯層）                                   │
│   - AuthService：登入、登出                                │
│   - LeaveCalculator：依時段算時數                          │
│   - ApprovalRouter：依規則決定要走幾關                    │
│   - NotificationService：發送通知                         │
│   - EmailSender：寄 Email                                 │
└──────────────────────────┬───────────────────────────────┘
						   ▼
┌──────────────────────────────────────────────────────────┐
│  Data（資料存取層）                                       │
│   - AppDbContext：EF Core 進入點                          │
│   - SeedData：初始種子資料                                │
└──────────────────────────┬───────────────────────────────┘
						   ▼
┌──────────────────────────────────────────────────────────┐
│  SQL Server（持久化儲存）                                 │
└──────────────────────────────────────────────────────────┘
```

## 2. 為什麼要分層？

| 層次 | 職責 | 不應該做 |
|------|------|----------|
| Controllers | 路由、模型繫結、驗證、回傳 View | 寫 SQL、複雜運算 |
| Services | 商業規則、計算、流程編排 | 處理 HTTP 細節 |
| Data | 資料存取、Entity 設計 | 寫商業邏輯 |

好處：
- **可替換**：未來想換 PostgreSQL，只需改 Data 層；換 React 前端，只需改 Controllers。
- **可測試**：Services 不依賴 HTTP，可以寫單元測試。
- **可閱讀**：每個檔案職責單一，新人接手不會迷路。

## 3. Cookie 認證流程

```
1. 瀏覽器 → POST /Account/Login（帳號密碼）
				 │
				 ▼
2. AccountController.Login
	   └→ AuthService.ValidateAsync（查 DB + BCrypt 驗證）
			  │ 成功
			  ▼
3. AuthService.SignInAsync
	   └→ 建立 ClaimsPrincipal（含 UserId、Username、各 Role 一筆 Claim）
	   └→ HttpContext.SignInAsync 寫 Cookie
			  │
			  ▼
4. 瀏覽器收到 Set-Cookie，後續每次請求都帶這個 Cookie
			  │
			  ▼
5. 下次請求 → UseAuthentication 中介軟體解析 Cookie → 還原 User
													   │
													   ▼
6. UseAuthorization 檢查 [Authorize(Roles="Admin")] 是否符合
```

## 4. 一次 HTTP 請求生命週期（範例：學員提交請假）

| 順序 | 發生地點 | 做什麼 |
|------|----------|--------|
| 1 | 瀏覽器 | 送出 POST /LeaveRequest/Create |
| 2 | UseRouting | 找到 LeaveRequestController.Create |
| 3 | UseAuthentication | 讀 Cookie，還原 User |
| 4 | UseAuthorization | 檢查 [Authorize(Roles="Student")] |
| 5 | Controller | ModelState.IsValid 驗證 |
| 6 | Controller | 呼叫 LeaveCalculator 算時數 |
| 7 | Controller | 呼叫 ApprovalRouter 決定關卡 |
| 8 | Controller | 寫入 AppDbContext.LeaveRequests + Steps |
| 9 | Controller | 呼叫 NotificationService 通知簽核人 |
| 10 | Controller | RedirectToAction("MyRequests") |
| 11 | 瀏覽器 | 收到 302，跳轉 /LeaveRequest/MyRequests |

## 5. 為什麼用 EF Core Code First？

- C# 類別 = 資料表結構，**單一事實來源**。
- 自動產生 Migration 腳本，避免手寫 SQL 出錯。
- Schema 變更有版本控制（Migrations 資料夾），可以回溯。
- 注意：**不要直接到 SSMS 改表結構**，否則會與 Migration 不同步。
