1. 建立專案

找一個你放程式碼的地方（例如 D:\code\），開終端機，執行：

終端機建立專案
dotnet new mvc -o MyLeaveSystem
cd MyLeaveSystem
部分意思
dotnet new從範本建立新專案
mvc要用「ASP.NET Core MVC」這個範本。 （另外還有 console、webapi、blazor 等）
-o MyLeaveSystem輸出到 MyLeaveSystem 這個資料夾， 專案名稱也會叫這個
想在 Visual Studio 裡做也可以 「建立新專案」→ 搜尋「ASP.NET Core Web 應用程式（Model-View-Controller）」→ 名稱填 MyLeaveSystem → 架構選 .NET 10.0， 「驗證類型」保持無（我們第 10 章要自己做）。產生的東西跟上面的指令一模一樣。

2. 跑起來

終端機在 MyLeaveSystem 資料夾裡
dotnet run

你會看到類似這樣的輸出：

輸出終端機
info: Microsoft.Hosting.Lifetime[14]
      Now listening on: https://localhost:7123
info: Microsoft.Hosting.Lifetime[14]
      Now listening on: http://localhost:5123
info: Microsoft.Hosting.Lifetime[0]
      Application started. Press Ctrl+C to shut down.

把那個 https://localhost:7123 貼到瀏覽器（你的埠號會不一樣， 以自己終端機印出來的為準），應該會看到一個寫著「Welcome」的頁面。

恭喜，你有一個網站了。要停止它，回終端機按 Ctrl+C。

常見錯誤一：瀏覽器說「您的連線不是私人連線」

這是本機開發用的自簽憑證，瀏覽器不認識它。 點「進階」→「繼續前往 localhost」就好。想一勞永逸的話執行一次：

dotnet dev-certs https --trust

然後重開瀏覽器。（macOS / Windows 會跳出確認視窗，按同意。）

常見錯誤二：Address already in use

埠號被佔用了——通常是你上次 dotnet run 沒關乾淨。 找到那個終端機視窗按 Ctrl+C，或直接指定別的埠：

dotnet run --urls http://localhost:5199

3. 每個資料夾是什麼

用編輯器打開 MyLeaveSystem 資料夾，你會看到：

MyLeaveSystem/ ├── Controllers/ ← C：接請求、決定回什麼 │ └── HomeController.cs ├── Models/ ← M：資料長什麼樣 │ └── ErrorViewModel.cs ├── Views/ ← V：畫面長什麼樣（.cshtml） │ ├── Home/ │ │ ├── Index.cshtml │ │ └── Privacy.cshtml │ ├── Shared/ │ │ ├── _Layout.cshtml ← 每頁共用的外框 │ │ ├── _Layout.cshtml.css │ │ ├── Error.cshtml │ │ └── _ValidationScriptsPartial.cshtml │ ├── _ViewImports.cshtml ← 所有 View 共用的 using │ └── _ViewStart.cshtml ← 所有 View 預設套哪個 Layout ├── wwwroot/ ← 靜態檔案，瀏覽器可直接下載 │ ├── css/site.css │ ├── js/site.js │ ├── lib/ ← Bootstrap、jQuery 都放這 │ └── favicon.ico ├── Properties/ │ └── launchSettings.json ← 本機啟動設定（埠號等） ├── appsettings.json ← 設定檔（之後放連線字串） ├── appsettings.Development.json ← 開發環境專用，會蓋掉上面那份 ├── Program.cs ← 整支程式的進入點 ├── MyLeaveSystem.csproj ← 專案設定與套件清單 ├── bin/ obj/ ← 編譯產物，不用管、不要進版控
為什麼 wwwroot 要獨立出來？

只有 wwwroot 裡的檔案，瀏覽器能直接用網址抓到。 wwwroot/css/site.css → 網址是 /css/site.css。

這是一道安全界線：你的 Program.cs、appsettings.json （裡面有資料庫密碼！）都在 wwwroot 外面，沒有人能用網址把它們載走。

底線開頭的檔案 _Layout.cshtml、_ViewStart.cshtml、_ViewImports.cshtml—— 開頭是 _ 的 View 是給別的 View 用的零件， 使用者不會直接瀏覽到它們。這是慣例，不是語法規定。

4. Program.cs 逐行拆解

打開 Program.cs，範本產生的內容大概是這樣（我把註解翻成中文）：

C#Program.cs（範本原始內容）
var builder = WebApplication.CreateBuilder(args);

// ── 第一段：登記服務 ──
builder.Services.AddControllersWithViews();

var app = builder.Build();     // ← 分界線

// ── 第二段：組出請求處理管線 ──
if (!app.Environment.IsDevelopment())
{
    app.UseExceptionHandler("/Home/Error");
    app.UseHsts();
}

app.UseHttpsRedirection();
app.UseRouting();

app.UseAuthorization();

app.MapStaticAssets();

app.MapControllerRoute(
    name: "default",
    pattern: "{controller=Home}/{action=Index}/{id?}")
    .WithStaticAssets();

app.Run();

整個檔案只有兩段，中間被 var app = builder.Build(); 切開。 這個分界非常重要：

上半段（Build 之前）下半段（Build 之後）
在做什麼 登記「我這個程式會用到哪些服務」 組出「每個請求要依序經過哪些處理」
關鍵字 builder.Services.Add… app.Use… / app.Map…
執行次數 兩段都只在啟動時跑一次。之後每個請求走的是下半段組出來的管線。

4.1 上半段：AddControllersWithViews()

這一行告訴框架：「我要用 MVC，請把 Controller 掃描出來、把 Razor 引擎準備好」。 沒有它，你的 HomeController 就只是一個沒人理的普通類別。

後面章節你會在這裡愈加愈多行：第 6 章加 AddDbContext（資料庫）、 第 9 章加 AddScoped（自己的服務）、第 10 章加 AddAuthentication（登入）。

4.2 下半段：每個 app.Use… 是一層

把一個 HTTP 請求想像成過安檢： 它要一關一關通過，每一關都可以檢查、修改，甚至直接把它擋下來退回去。 每個 app.UseXxx() 就是一關，順序就是註冊的順序。

這一關做什麼
UseExceptionHandler 包在最外面。裡面任何一關爆炸，都由它接住並顯示友善錯誤頁。 只在非開發環境啟用——開發時你反而想看到完整的錯誤堆疊。
UseHttpsRedirection 用 http:// 進來的，轉去 https://。
UseRouting 看網址，決定「這個請求該交給哪個 Controller 的哪個 Action」。 注意：只是「決定」，還沒真的執行。
UseAuthorization 檢查「這個人能不能存取剛才決定好的那個 Action」。第 10 章的主角。
MapStaticAssets 如果網址對應到 wwwroot 裡的檔案，直接回傳檔案，不用麻煩 Controller。
MapControllerRoute 真正把請求交給 Controller 執行。
app.Run() 開始監聽。這一行會一直卡住不返回，直到你按 Ctrl+C。

5. 中介軟體管線：順序為什麼重要

用實際的例子感受一下。UseRouting 一定要在 UseAuthorization 前面，因為：

  1. UseRouting 先看網址，算出「這個請求要去 AdminController.Users」。
  2. UseAuthorization 才知道要去看 AdminController.Users 上面掛了什麼權限規則。

順序反過來的話，授權那一關根本還不知道要檢查哪個 Action 的規則，等於形同虛設。

這種錯不會有編譯錯誤

管線順序寫錯編譯完全正常，網站也跑得起來—— 只是安全檢查悄悄失效，或者所有頁面莫名其妙都變成拒絕存取。

這就是為什麼要把順序背起來： Routing → Authentication →Authorization → Map。 （UseAuthentication 你現在還沒有，第 10 章會加。）

5.1 親眼看一次管線

在 UseRouting() 上面插一段自己的中介軟體，印出每個請求的網址：

修改Program.cs
app.UseHttpsRedirection();

// 臨時：把每個進來的請求印出來（本節結束後刪掉）
app.Use(async (context, next) =>
{
    Console.WriteLine($"→ 進來了：{context.Request.Method} {context.Request.Path}");
    await next();                       // 交給下一關
    Console.WriteLine($"← 回去了：{context.Response.StatusCode}");
});

app.UseRouting();

存檔、dotnet run、開瀏覽器，看終端機：

輸出終端機
→ 進來了：GET /
← 回去了：200
→ 進來了：GET /lib/bootstrap/dist/css/bootstrap.min.css
← 回去了：200
→ 進來了：GET /favicon.ico
← 回去了：200
注意 await next() 的前後都有輸出

這說明管線是雙向的：請求「進去」時經過每一關， 回應「出來」時再反向經過一次。

所以 UseExceptionHandler 放在最外層才有意義—— 它要能接住從裡面任何一層丟出來的例外。

看完之後把這段刪掉，它只是拿來理解用的。

6. .csproj 是什麼

XMLMyLeaveSystem.csproj
<Project Sdk="Microsoft.NET.Sdk.Web">

  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
  </PropertyGroup>

</Project>
設定意思
Sdk="…Sdk.Web"這是個網站專案（相對於 Microsoft.NET.Sdk 是一般專案）
TargetFramework要跑在 .NET 10 上
Nullable第 1 章第 3 節講的 null 檢查，打開
ImplicitUsings常用的 using（System、System.Linq 等） 自動幫你加，所以你的檔案上面才不用寫一長串

你的 .csproj 現在沒有任何套件參考。 第 6 章裝 EF Core、第 10 章裝 BCrypt 時，這裡會多出 <PackageReference> 區塊。

重要慣例：一個 class 一個檔案，檔名 = 類別名 C# 沒有強制，但所有專案都這樣做。 LeaveType 類別就放在 LeaveType.cs。 你等一下建新檔案時請遵守，不然找檔案會找到瘋掉。

7. 動手：改掉首頁

最後做一個小改動，確認你的修改真的會反映到畫面上。打開 Views/Home/Index.cshtml：

修改Views/Home/Index.cshtml
@{
    ViewData["Title"] = "首頁";
}

<div class="text-center">
    <h1 class="display-4">學生請假系統</h1>
    <p>線上化請假流程，三方協作更有效率。</p>
    <p class="text-muted">現在時間：@DateTime.Now.ToString("yyyy-MM-dd HH:mm:ss")</p>
</div>

存檔、重新整理瀏覽器。應該會看到新標題，而且每次重新整理時間都會變。

那個 @ 是什麼？

.cshtml 是 Razor 檔案：HTML 裡面可以插 C#。 @ 就是「接下來這段是 C#，請執行它、把結果印出來」。

所以 @DateTime.Now… 是在伺服器上執行的， 每次請求都會重算一次，然後把算出來的字串放進送給瀏覽器的 HTML 裡。 第 4 章整章都在講 Razor。

不用每次都重啟 改 .cshtml 通常存檔後重新整理就生效。 但改 .cs（C# 程式碼）需要重新編譯—— 用 dotnet watch run 取代 dotnet run，它會自動偵測並重啟。 Visual Studio 按 F5 有內建的「熱重載」，效果一樣。
改了沒反應？

三個嫌疑犯，依序檢查：

① 檔案沒存檔。② 改的是 .cs 但沒重新編譯。 ③ 瀏覽器快取——按 Ctrl+F5 強制重新整理。

8. 你現在的專案長什麼樣

一個能跑的空殼網站：有首頁、有隱私權頁、套了 Bootstrap 樣式， 但沒有資料庫、沒有登入、沒有任何業務功能。

接下來三章會把 MVC 的三個字母各講一遍：

  • 第 3 章：網址是怎麼變成 HomeController.Index() 這個方法呼叫的（C）
  • 第 4 章：資料是怎麼從 Controller 跑到畫面上的（V）
  • 第 5 章：使用者填的表單是怎麼變回 C# 物件的（M）
