# 09 — 學習路徑

本文件是給「**第一次認識這個專案**」或「**想系統性理解全貌**」的人看的學習指南。

設計原則：
- 按「**主題模組**」組織，不按 Phase 切，主題永遠穩定（CRUD 永遠是 CRUD）。
- 每個模組都有「**讀什麼 → 動手做什麼 → 怎麼驗證自己懂了**」三段。
- 隨著 Phase 推進，§8 進階模組會持續擴充。

---

## 1. 開始之前

### 1.1 先確認您能跑起來

如果還沒，請先完成 [`06-開發環境設定.md`](./06-開發環境設定.md) 的步驟，
能用 `Admin / Admin@123` 登入後再開始閱讀本文件。

### 1.2 學習過程的 4 個原則

1. **看不懂的先記下來** — 開一個 `docs/99-我的疑問.md`（這份不會 commit），慢慢累積。
2. **F9 + F10 是您最好的朋友** — 讀程式碼不如跟著它跑一遍。
3. **每天最多 2 小時** — 大腦消化得了的份量比一次塞滿重要。
4. **可以隨時跳章** — 模組之間相對獨立，覺得無聊就跳。

### 1.3 隨時可以問

學習過程中卡住，直接告訴 AI 助手：
- 「解釋 `Program.cs` 第 X 行」
- 「Claims 是什麼？」
- 「為什麼這樣寫？」
- 「我改了 XX 但壞了，這是錯誤訊息：…」

## 5. 模組 C：資料模型與 EF Core

**目標**：看懂 Entity、DbContext、SeedData 三者關係，知道資料如何從程式變成資料表。

### 5.1 讀什麼

| 順序 | 文件 / 檔案 | 重點 |
|------|------------|------|
| 1 | [`03-資料模型.md`](./03-資料模型.md) | 所有 Entity 的設計與關係 |
| 2 | `Models/Enums/UserRole.cs` | 最簡單的 enum |
| 3 | `Models/Entities/UserAccount.cs` | 最重要的 Entity |
| 4 | `Models/Entities/Role.cs` + `UserRole.cs` | 多對多關聯範例 |
| 5 | `Data/AppDbContext.cs` | 整支讀完，重點看 OnModelCreating |
| 6 | `Data/SeedData.cs` | 種子資料怎麼寫 |

### 5.2 動手做：對照程式碼與真實資料表

1. 開 SSMS 連到 `.`，展開 `Databases → LeaveSystem → Tables`。
2. 找 `dbo.Roles` 右鍵 `Select Top 1000 Rows`，看實際資料。
3. 對照 `SeedData.cs` 第 49~56 行的 AddRange — 跟資料表一樣嗎？
4. 試查 `UserAccounts`、`UserRoles` 看 Admin 的資料如何串起來：
   ```sql
   SELECT u.Username, r.Name AS Role
   FROM UserAccounts u
   JOIN UserRoles ur ON u.Id = ur.UserId
   JOIN Roles r ON ur.RoleId = r.Id;
   ```

### 5.3 自我驗證

- ✅ 解釋「Entity 與 Table 的對應關係」。
- ✅ 解釋為什麼 `Role.Id` 要寫 `ValueGeneratedNever()`（提示：種子資料寫死 Id）。
- ✅ 說出 `OnModelCreating` 何時被執行。
- ✅ 說出多對多關係為什麼要拆出 `UserRole` 中介表。

## 9. 學習小撇步

### 9.1 看不懂時的「3 步法」

1. **先讀註解** — 本專案有大量中文 XML 註解，先看意圖再看實作。
2. **再看流程** — F9 + F10 跟著程式碼走一遍。
3. **最後看細節** — `async`、`Scoped`、generics 這些可以延後。

### 9.2 把 Visual Studio 這幾個視窗開好

| 視窗 | 用途 | 開啟方式 |
|------|------|---------|
| 方案總管 | 看檔案結構 | Ctrl+Alt+L |
| 輸出 | 看 EF Core 實際送的 SQL | View → Output |
| 呼叫堆疊 | 偵錯時看誰呼叫誰 | Debug → Windows → Call Stack |
| 即時運算 | 偵錯時 C# 互動 | Debug → Windows → Immediate |
| 錯誤清單 | 編譯錯誤與警告 | Ctrl+\, E |

### 9.3 觀察 EF Core 實際送的 SQL

在 `appsettings.Development.json` 加：
```json
"Logging": {
  "LogLevel": {
	"Microsoft.EntityFrameworkCore.Database.Command": "Information"
  }
}
```

啟動後在「輸出」視窗就能看 EF Core 實際送出的 SQL 語句，
這對理解 LINQ 怎麼變 SQL 非常有幫助。

### 9.4 改了東西不小心搞壞？

```powershell
git status            # 看哪些檔案被改了
git diff 檔案路徑     # 看具體變更
git restore 檔案路徑  # 還原這個檔（沒 commit 才能用）
```

## 10. FAQ

### Q1：一定要按順序讀嗎？

**前 5 個模組（A~E）建議照順序**，互相依賴。
進階模組（F 之後）可以挑有興趣的先看。

### Q2：要花多久才能「真的會」？

| 階段 | 大概時間 |
|------|---------|
| 看完模組 A~E（能看懂程式碼）| 5~7 天，每天 1~2 小時 |
| 會自己改小功能 | 2~3 週 |
| 會自己加新 Phase 功能 | 1~2 個月 |

### Q3：看不懂可以略過嗎？

可以，但**標記下來**（記在 `docs/99-我的疑問.md`），過幾天回來常會自己想通。

### Q4：可以跳到自己有興趣的部分嗎？

可以，但建議至少看完 §3 模組 A 建立心智模型，否則容易迷路。

### Q5：學完之後想擴充功能怎麼開始？

1. 先想清楚「使用者要解決什麼問題」（需求）。
2. 開新分支 `feature/xxx-yyy`。
3. 按模組 B、C、D、E 提到的順序：先動 Entity → 再 Service → 再 Controller → 最後 View。
4. 邊做邊更新 docs。
