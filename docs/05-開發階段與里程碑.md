# 05 — 開發階段與里程碑

## 整體規劃

本系統採「**整體規劃 + 分階段實作**」方式：每個 Phase 完成後驗證可用，再進下一個 Phase。

## Git 分支策略

- 主分支：`master`
- 每個 Phase 開 `feature/phaseN-xxx` 分支
- 完成驗證後 `git merge --no-ff` 回 master，並打 tag

## Phase 進度

| Phase | 狀態 | Tag | 內容 |
|-------|------|-----|------|
| 0 | ✅ 完成 | v0.1-phase0 | 基礎建設 |
| 1 | ✅ 完成 | v0.2-phase1 | 自訂登入與帳號管理 |

| 3 | 🚧 下一個 | v0.4-phase3 | 學員請假申請 |

## Phase 0：基礎建設 ✅ 已完成（tag `v0.1-phase0`）

**目標**：搭好骨架與資料模型，讓專案可編譯、有完整文件。

**交付物**：

- 11 個 Entity 類別
- AppDbContext + SeedData
- 連線字串
- _Layout 與 Home 頁繁中化
- 9 篇 docs

**驗證**：
1. `dotnet build` 成功
2. F5 可看到中文首頁
3. 文件可讀

## Phase 1：自訂登入與角色授權 ✅ 已完成（tag `v0.2-phase1`）

**目標**：所有角色可登入，行政可後台建帳號。

**交付物**：
- IPasswordHasher / IAuthService 服務（BCrypt + Cookie）
- AccountController（Login、Logout、AccessDenied）
- Admin/UsersController（建立、編輯、重設密碼、停用啟用）
- Cookie 認證設定（8 小時、SlidingExpiration、HttpOnly）
- _Layout 加登入/登出 UI、_LoginPartial
- 預設管理員：`Admin / Admin@123`

**驗證**：
1. ✅ 用預設 Admin/Admin@123 可登入
2. ✅ 登入後可建立其他角色帳號
3. ✅ 各角色登入後看得到對應功能連結
4. ✅ 非 Admin/Staff 訪問 /Admin/Users 會被導到 AccessDenied

**已知限制（待 Phase 2 解決）**：
- 新增使用者時「所屬班期」下拉是空的（班期表還沒資料）
- 學員若需綁定班期，要等 Phase 2 完成後再建

## Phase 2：班期、假別、簽核規則 CRUD ✅ 已完成（tag `v0.3-phase2`）

**目標**：行政可維護組織與規則資料。

**交付物**：
- CohortController + Views（建立班期、指派導師/科長/分署長）
- LeaveTypeController + Views（增刪改查假別）
- ApprovalRuleController + Views（調整簽核門檻）

**驗證**：
1. 建立一個班期、設定 900 小時、預設 10%
2. 建立 4 個假別
3. 確認 3 條預設簽核規則可調整

## Phase 3：學員請假申請

**目標**：學員可線上提交請假申請。

**交付物**：
- LeaveCalculator 服務（依時段算時數）
- LeaveRequestController + Views（提交、查詢自己的單）
- 時段下拉選單元件

**驗證**：
1. 學員登入後可送出 1 小時申請
2. 系統正確計算時數（含跨午休）
3. 超過班期上限時阻擋

## Phase 4：簽核引擎

**目標**：自動派送、逐級簽核、駁回流程。

**交付物**：
- ApprovalRouter 服務（派送邏輯）
- ApprovalController + Views（簽核人視角）
- 簽核狀態機

**驗證**：
1. 提交 24 小時申請會走 3 級簽核
2. 任一級駁回整張單終止
3. 學員可看到完整簽核歷程

## Phase 5：紀錄查詢與時數統計
