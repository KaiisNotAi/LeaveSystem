📖 系統概述

本系統取代原本以 LINE + 紙本假單 處理學員請假的舊流程，讓學員、簽核者（導師 / 科長 / 分署長）、行政人員三方在同一平台上作業。

核心功能

🎓 學員端

  • 線上填寫並送出請假申請
  • 即時查看簽核進度與簽核意見
  • 查詢個人歷史請假紀錄
  • 檢視各假別累計時數與班期上限
  • 查閱個人曠課紀錄（唯讀）

✅ 簽核者端

  • 待辦清單集中檢視
  • 逐級簽核（核准 / 駁回）
  • 簽核意見留存供追溯
  • Email 與站內雙通知

⚙️ 行政 / 管理員端

  • 使用者、班期、假別、簽核規則維護
  • 曠課紀錄登錄與管理
  • 行政彙總報表（班期 × 學員 × 假別 × 月份）
  • 報表匯出（CSV / Excel）

🔔 通知機制

  • 站內通知（🔔 圖示 + /Notifications）
  • Email 通知（開發環境走 PickupDirectory）
  • 4 個觸發點：送單、逐級通過、全通過、駁回

🔐 登入方式（共通）

  1. 開啟瀏覽器，前往系統首頁（例：https://localhost:5001）。
  2. 點擊右上角「登入」，前往 /Account/Login。
  3. 輸入行政人員配發給您的帳號與密碼。
  4. 登入成功後，系統會依您的角色顯示對應的功能選單。
  5. 操作完畢請點右上角「登出」以保護個人資料。

忘記密碼

目前系統未提供自助重設密碼功能，請聯絡行政人員 / 系統管理員至 /Admin/Users 使用「重設密碼」功能協助。

🎓 學員操作指南 Student

Pending 等待簽核
  1. 從上方選單進入「我要請假」或直接前往 /LeaveRequests/Create。
  2. 選擇假別（病假 / 事假 / 喪假 / 公假…）。
  3. 選擇起訖日期與時段（下拉選單，最小單位 1 小時，僅可選整點）。
  4. 填寫請假原因（必填）。
  5. 系統會即時顯示：
    • 計算後的總時數（扣除 12:00–13:00 午休、下班後 17:00 之後不計）
    • 是否超過班期請假上限（若超過將無法送出）
    • 依時數自動判斷需要幾關簽核
  6. 確認無誤後按「送出」，狀態即變為 Pending。
💡 送出時系統會建立所有關卡的 Step（例如需三關則建立 3 筆），並將 CurrentLevel = 1，通知第一關簽核者。

2. 查看我的請假紀錄與進度

  1. 前往 /LeaveRequests 檢視「我的請假清單」。
  2. 可依狀態、假別、日期篩選。
  3. 點擊單一列可看：目前停在第幾關、每一關的簽核人、簽核意見與時間戳。
狀態意義可做的動作
Pending簽核中可撤銷（若尚未有人核准）
Approved全關通過僅檢視
Rejected任一關駁回可重新申請新單
Cancelled學員自行撤銷僅檢視

3. 查看時數統計

  • /Reports/Index：可依狀態、假別、日期篩選我的請假紀錄。
  • /Reports/Summary：各假別已核准時數 + 班期上限進度條（只計 Approved 的單）。
📌 尚未指派班期的學員只會看到已核准時數，不顯示進度條並提示「尚未指派班期」。

4. 查看個人曠課紀錄

  1. 前往 /AbsenceRecords。
  2. 可依日期範圍篩選，並看到個人總曠課時數（此數字不受日期篩選影響，作為固定警惕值）。
❗ 曠課紀錄僅由行政人員登錄，學員無法自行新增 / 修改 / 刪除。若有疑義請洽行政。

✅ 簽核者操作指南 Tutor / SectionChief / BranchDirector

1. 處理待辦

收 🔔 通知
→
/Approvals 待辦清單
→
點入 Details
→
核准 或 駁回（填原因）
  1. 登入後點右上角 🔔 圖示，或直接進入 /Approvals。
  2. 清單只會顯示目前輪到您的單（Step.Level == CurrentLevel 且您是該關指定角色）。
  3. 點擊某筆進入 Details，檢視：申請人、假別、時段、總時數、請假原因、前一關的簽核意見。
  4. 選擇動作：
    • 核准：可填意見（選填）。若還有下一關，系統自動推進 CurrentLevel 並通知下一位；若是最後一關，整單變 Approved 並通知申請人。
    • 駁回：意見必填。整單立即變 Rejected，後續關卡不再處理，同時通知申請人並附上原因。

2. 誰能看到哪些單？

角色可見待辦條件
導師所屬班期學員的單 · CurrentLevel = 1 · 該關 Role = Tutor
科長所屬班期學員的單 · CurrentLevel = 2 · 該關 Role = SectionChief
分署長所屬班期學員的單 · CurrentLevel = 3 · 該關 Role = BranchDirector
🔑 關鍵規則：前一關未核准前，下一關不會看到該單。

3. 簽核規則對照（預設）

請假時數需經過的關卡
≤ 8 小時導師（1 關）
8.01 ~ 24 小時導師 → 科長（2 關）
> 24 小時導師 → 科長 → 分署長（3 關）

規則由 ApprovalRule 表決定，可由系統管理員於 /Admin/ApprovalRules 調整。

💡 防呆：同一 Step 不能重複簽核；簽完會立刻寫入 ApproverUserId 與 DecidedAt，供追溯。

⚙️ 行政人員 / 系統管理員操作指南 Staff / Admin

1. 使用者管理（/Admin/Users）

  1. 建立新帳號：填寫姓名、Email、初始密碼、角色（可多選）。
  2. 指派學員的所屬班期（CohortId）— 未指派班期的學員無法被登錄曠課，也不會出現在多數彙總。
  3. 停用 / 啟用帳號（不建議直接刪除，以保留歷史紀錄）。
  4. 重設使用者密碼。
📌 建立學員前請先建立班期，否則「所屬班期」下拉將為空。

2. 班期管理（/Admin/Cohorts）

  • 建立班期名稱、起訖日期。
  • 設定班期請假上限時數（LeaveLimitHours），例如班期總上課時數 × 10%。
  • 指派該班期的導師 / 科長 / 分署長，決定學員送單後由誰簽核。

3. 假別管理（/Admin/LeaveTypes）

維護病假、事假、喪假、公假…等假別。此清單直接對應學員申請時的下拉選單。

4. 簽核規則管理（/Admin/ApprovalRules，僅 Admin）

調整時數區間對應的簽核角色鏈。每筆規則含：

  • MinHours / MaxHours：時數區間（MaxHours 可為空表示無上限）
  • RequiredRoles：JSON 陣列，例如 ["Tutor","SectionChief"]

5. 曠課紀錄管理（/Admin/AbsenceRecords）

選班期
→
選學員（自動過濾）
→
填曠課時間 / 時數 / 備註
→
送出
  1. Create：兩層下拉先選班期，再選該班學員；時數必為正整數 1–100（不接受 1.5 這種小數）。
  2. Edit：進入時會自動反推該學員所屬班期；編輯不會覆寫原始建立者與建立時間，保留追溯。
  3. Delete：以 POST 方式刪除，並會請求二次確認。
  4. 清單支援日期篩選（DateFrom / DateTo，DateTo 語意為「含當天」）。
❗ 曠課紀錄與請假單完全獨立，不會影響任何簽核狀態；同一天可同時存在「已核准請假」與「曠課紀錄」（例：上午請假、下午未到）。

6. 行政彙總報表（/Reports/Admin）

  • 維度：Cohort × Student × LeaveType × YearMonth（四層 GroupBy）。
  • 只統計 Approved 的請假單，維持與班期上限檢查一致。
  • 跨月切法：跨月請假整筆歸入「開始月」，不拆分（與人工判讀一致）。
  • 可依班期、學員、假別、日期範圍篩選；日期篩選僅決定納入計算的單，不影響月份分組。

7. 資料匯出（/Admin/Export）

依目前報表的篩選條件匯出 CSV / Excel，方便貼進機構自有的統計工具。

行政操作最佳實踐

✅ 建議流程：
① 開學前建 班期並指派簽核人 → ② 建學員帳號並指派班期 → ③ 上線期間每週或每日登錄曠課 → ④ 月底看 Reports/Admin彙總、匯出報表存檔。

❓ 常見問題 FAQ

Q1：學員送單時系統擋住「將超過班期上限」怎麼辦？

代表已核准時數 + 本次申請超過該班期 LeaveLimitHours。請縮短本次請假時數，或洽行政確認上限是否需調整。

Q2：明明送單了，簽核人卻說沒看到？

請確認：
(1) 該學員是否已指派班期；
(2) 該班期是否已指派對應層級的簽核人；
(3) 目前是否停在該簽核人這一關（CurrentLevel 是否等於他的 Level）。

Q3：簽核駁回後可以撤銷嗎？

不可以。整單狀態為 Rejected 後為終態；學員需要時請重新建立新單。

Q4：新增學員時「所屬班期」下拉是空的？

請先至 /Admin/Cohorts 建立班期，再回來新增學員。

Q5：學員可以自己填曠課嗎？

不行。曠課由行政事後登錄，學員僅能於 /AbsenceRecords 查閱自己的紀錄。

Q6：Email 收不到通知？

開發環境是 PickupDirectory，不會真的寄信，請到專案 ./mail-pickup/ 檢視 .eml。正式環境請確認：
(1) appsettings.Production.json 或環境變數已設定 SMTP；
(2) 使用者 Email 欄位有值；
(3) 檢查 SMTP 服務是否可連線（防火牆 / 埠號）。

Q7：跨月請假在報表中歸哪個月？

整筆歸入開始月，不拆分。例：6/28 08:00 ~ 7/2 17:00 全部歸 6 月。

Q8：忘記密碼？

請洽行政 / 系統管理員至 /Admin/Users 使用「重設密碼」。
