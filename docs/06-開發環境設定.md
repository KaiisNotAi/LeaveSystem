第一次拿到專案的人，請依照本文件從零開始把它跑起來。

## 2. SQL Server 設定

### 2.1 確認 SQL Server 已啟動

按 Win 鍵 → 搜尋「SQL Server 組態管理員」→ 確認「SQL Server (MSSQLSERVER)」狀態為「執行中」。

如果是 SQL Server Express，預設執行個體名稱可能是 `SQLEXPRESS`，連線字串要改：
```
Server=.\SQLEXPRESS;...
```

### 2.2 用 SSMS 測試連線

1. 開啟 SSMS
2. 伺服器名稱輸入 `.`（代表本機預設執行個體）或 `.\SQLEXPRESS`
3. 驗證類型選「Windows 驗證」
4. 按連線

如果連得進去，就 OK。

## 3. 修改連線字串（如有需要）

預設連線字串在 `appsettings.json` 與 `appsettings.Development.json`：

```json
"ConnectionStrings": {
  "DefaultConnection": "Server=.;Database=LeaveSystem;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=true"
}
```

| 設定 | 說明 |
|------|------|
| Server=. | 連到本機預設執行個體 |
| Database=LeaveSystem | 資料庫名稱（不存在會由 EF Core 建立） |
| Trusted_Connection=True | 用 Windows 帳號登入 |
| TrustServerCertificate=True | 略過 SSL 憑證驗證（開發機常用） |
| MultipleActiveResultSets=true | 允許同連線多個結果集 |

如果是 SQLEXPRESS，把 `Server=.` 改成 `Server=.\SQLEXPRESS`。

## 4. 建立資料庫（首次 + 每次模型變更後）

### 4.1 安裝 EF Core CLI 工具（只需一次）

```powershell
dotnet tool install --global dotnet-ef
```

如果已安裝過，更新版本：
```powershell
dotnet tool update --global dotnet-ef
```

### 4.2 產生 Migration（每次 Entity 變更後）

```powershell
cd E:\伺服器程式\LeaveSystem
dotnet ef migrations add Init
```

執行後會在 `Migrations/` 資料夾出現一個含時間戳記的 `xxx_Init.cs`，這就是「資料庫變更腳本」。

### 4.3 套用到資料庫

```powershell
dotnet ef database update
```

EF Core 會：
1. 連到 `Server=.`
2. 如果 `LeaveSystem` 資料庫不存在，自動建立
3. 執行 Migration 腳本，建好所有資料表

執行成功後到 SSMS 重新整理「資料庫」節點，就會看到 `LeaveSystem`。

### 4.4 ⚠️ 重要警告：不要直接在 SSMS 改表結構！

EF Core Migration 是「資料庫的版本控制」，每次變更都有歷史。如果你直接在 SSMS：
- 新增欄位
- 修改型別
- 刪除索引

**EF Core 不知道這些變更**，下次 `dotnet ef database update` 時會以為資料庫還是舊版，可能：
- 套用失敗
- 資料遺失
- 錯誤訊息看不懂

**正確做法**：所有 schema 變更都從 Entity 類別出發，再 `dotnet ef migrations add 名稱` 產生新 Migration。

SSMS 的正確用途：
- ✅ 觀察資料表內容（SELECT）
- ✅ 寫查詢測試
- ✅ 備份還原
- ❌ 改 schema（CREATE/ALTER/DROP TABLE）

## 5. 執行專案

### 5.1 用 VS 2026

1. 開啟 `LeaveSystem.sln`
2. 按 F5（Debug）或 Ctrl+F5（無偵錯）
3. 瀏覽器自動開啟 `https://localhost:xxxx`

```powershell
cd E:\伺服器程式\LeaveSystem

```

## 6. Phase 1 完成後的測試帳號

預設管理員：
- 帳號：`Admin`
- 密碼：`Admin@123`

**首次登入後請立刻改密碼**！

之後請用此帳號到「使用者管理」建立其他角色帳號（行政、導師、科長、分署長、學員）。

### 6.1 Phase 1 驗證步驟（執行專案後）

1. 啟動專案後瀏覽器會自動開啟首頁。
2. 因為首頁已加 `[Authorize]`，會被自動導到 `/Account/Login`。
3. 用 `Admin / Admin@123` 登入。
4. 登入後右上角會顯示「您好，系統管理員」與「登出」按鈕。
5. 導覽列會出現「行政後台 → 使用者管理」連結（僅 Admin/Staff 看得到）。
6. 點進「使用者管理」可看到目前唯一的 Admin 帳號。
7. 試著「新增使用者」→ 建立一個導師、科長、分署長、學員，分別測試登入。
8. 用沒有 Admin/Staff 角色的帳號（如學員）登入後直接到 `/Admin/Users`，
   應被導到 `/Account/AccessDenied`（拒絕存取頁）。

確認以上 8 點都通過，Phase 1 即可結案。

## 7. Git 分支策略

### 7.1 主要分支

| 分支 | 用途 |
|------|------|
| `master` | 永遠保持可運作的穩定版 |
| `feature/phaseN-xxx` | 每個 Phase 的工作分支，完成後合併回 master |

### 7.2 開始一個新 Phase

```powershell
git checkout master
git pull
git checkout -b feature/phase2-cohort
```

### 7.3 工作中

```powershell
# 每完成一個邏輯里程碑就 commit
git add .
git commit -m "feat(phase2): 班期 CRUD 控制器"
```

### 7.4 完成 Phase

```powershell
# 1. push 工作分支（保留歷史）
git push -u origin feature/phase2-cohort

# 2. 切回 master 並合併
git checkout master
git merge --no-ff feature/phase2-cohort -m "Merge Phase 2：班期管理"

# 3. 打 tag
git tag -a v0.3-phase2 -m "Phase 2 完成：班期 CRUD"

# 4. push 到 GitHub
git push origin master --tags
```

### 7.5 Commit Message 慣例

| 前綴 | 用途 |
|------|------|
| `feat:` | 新功能 |
| `fix:` | 修 Bug |
| `docs:` | 改文件 |
| `refactor:` | 重構（不改行為） |
| `chore:` | 雜項（套件升級、設定） |
| `test:` | 加/改測試 |

範例：
```
feat(phase3): 學員提交請假表單
fix: 修正時數計算遇午休錯誤
docs: 更新資料模型文件
```

## 8. 常見問題排除

### Q：dotnet ef 指令找不到？
→ 安裝 EF Core CLI：`dotnet tool install --global dotnet-ef`

### Q：連線字串錯誤、找不到伺服器？
→ 確認 SQL Server Service 在跑；確認 `Server=.` 或 `.\SQLEXPRESS` 對應您的安裝。

### Q：build 時 NuGet 套件還原失敗？
→ 檢查 `dotnet nuget list source`，確認包含 `https://api.nuget.org/v3/index.json`。
   若沒有：`dotnet nuget add source https://api.nuget.org/v3/index.json --name nuget.org`

### Q：F5 後 IIS Express 拋例外？
→ 第一次跑可能要安裝開發用 SSL 憑證：`dotnet dev-certs https --trust`
