匯出 CSV / Excel

一次 GET 就要吐出一個含三個工作表的 .xlsx。 關鍵設計是把「欄位長什麼樣」抽成 ExportColumn<T> 這個純資料定義， 同一份定義同時餵給 CSV 與 Excel 兩個輸出器—— 改欄位只要改一個地方，兩種格式一起跟著變。

欄寬的小插曲
ClosedXML 的 AdjustToContents() 對中文會估得偏窄。 因此輸出器在自動調整後又補了 +2 的 padding， 並限制下限 8、上限 60，避免出現「###」或超寬欄。
9 → byte[] Services/Export/ClosedXmlExcelExporter.cs

輸出器回傳的是記憶體中的位元組陣列， 整個流程不落地成暫存檔——不用管清理，也不會有並行寫同一個檔名的問題。

CSV 的兩個細節

細節為什麼
UTF-8 含 BOM Excel 開純 UTF-8（無 BOM）的 CSV 時，中文會變成亂碼—— 它會猜成系統的 ANSI 編碼。加上 BOM 這 3 個位元組，Excel 才認得出是 UTF-8。
RFC 4180 跳脫 欄位值裡有逗號、雙引號或換行時，整欄要用雙引號包起來， 內部的雙引號要重複一次。請假原因是自由輸入的文字， 使用者很容易打進逗號——沒處理就會整個欄位錯位。

這兩件事都在 Services/Export/CsvExporter.cs 裡， 並有對應的單元測試 LeaveSystem.Tests/Services/CsvExporterTests.cs。

為什麼欄位定義要寫成 static readonly 陣列

ExportController.cs:197 / :212 / :224 定義了三組欄位： 

private static readonly IReadOnlyList<ExportColumn<AdminLeaveDetailRow>> LeaveDetailColumns = new[]
{
    new ExportColumn<AdminLeaveDetailRow>("班期",   r => r.CohortName),
    new ExportColumn<AdminLeaveDetailRow>("起始",   r => r.StartAt,    ExportValueType.DateTime),
    new ExportColumn<AdminLeaveDetailRow>("時數",   r => r.TotalHours, ExportValueType.Hours),
    // …
};
  • 只建立一次：static readonly 不會每次請求都重新 new 一遍。
  • CSV 與 Excel 共用：ExportLeavesCsv（:85） 與 ExportXlsx（:61）用的是同一個 LeaveDetailColumns，兩種格式的欄位順序與標題永遠一致。
  • 改欄位只改一處：要加一欄「駁回原因」， 在陣列裡加一行就好，兩種格式同時生效。

自己動手驗證

  1. 直接開 /Admin/Export/ExportXlsx（不帶 CohortId）， 看它把你導回設定頁。
  2. 在 LeaveDetailColumns 裡把「時數」那欄的 ExportValueType.Hours 改成 Text，重新匯出—— Excel 裡那一欄會變成靠左的文字、無法加總。看過就改回來。
  3. 把某張假單的請假原因填成 今天,明天"都"要請，匯出 CSV 用記事本打開， 看 RFC 4180 的跳脫長什麼樣。
  4. 用記事本把匯出的 CSV 另存成「UTF-8（無 BOM）」再用 Excel 開， 親眼看中文變亂碼。
  5. 跑 dotnet test --filter ExcelExporterTests， 看測試是怎麼在不開 Excel 的情況下驗證產出的。
