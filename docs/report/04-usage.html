CHAPTER 04

使用說明

怎麼把系統跑起來？三個角色分別怎麼操作？
本章提供環境建置步驟、預設帳號，以及學員 / 簽核人 / 行政的完整操作流程。

4.1 環境需求

項目版本 / 說明
作業系統Windows 10 / 11（macOS、Linux 亦可）
.NET SDK.NET 10 SDK（含 EF Core CLI）
資料庫SQL Server 2019+ 或 SQL Server LocalDB / Express
開發工具Visual Studio 2026 Community 或 VS Code
瀏覽器Edge / Chrome / Firefox 最新版
選用Git（版本控管）、MailKit PickupDirectory 資料夾（開發時檢視 Email）

4.2 安裝步驟（4 步驟）

  1. 取得原始碼
    git clone https://github.com/KaiisNotAi/LeaveSystem.git
  2. 還原套件
    cd LeaveSystem　→　dotnet restore
  3. 建立資料庫（會自動套用 Migration 並塞入預設資料）
    dotnet ef database update
  4. 啟動系統
    dotnet run　→　瀏覽 https://localhost:5001

💡 若使用 Visual Studio：直接按 F5 即可完成建置與啟動。

4.3 首次登入

預設管理員

帳號Admin
密碼Admin@123
角色系統管理員（Admin）

⚠️ 正式部署前務必變更密碼。

建議首次操作

  1. 登入後至 /Admin/Users 建立行政、導師、學員帳號
  2. 至 /Admin/Cohorts 建立班期並指派簽核人
  3. 至 /Admin/LeaveTypes 確認假別
  4. 至 /Admin/ApprovalRules 檢視三條預設簽核門檻

4.4 學員操作流程

登入
→
請假申請
/LeaveRequests/Create
→
等待簽核
→
🔔 收通知
→
結果通知

操作要點

  • 選擇假別 → 選日期與時段（整點）→ 填原因 → 送出
  • 系統即時顯示計算後時數，並告知是否超過班期上限
  • 可於 /LeaveRequests 追蹤每張單目前停在第幾關、誰簽的、意見
  • 於 /Reports/Summary 查看各假別累計時數與上限進度

4.5 簽核人操作流程

收 🔔 通知
→
/Approvals
待辦清單
→
Details 檢視
→
核准
或
駁回（填原因）

關鍵規則

  • 只看得到 目前輪到自己 的待辦（Level 必須等於 CurrentLevel）
  • 導師（Level 1）→ 科長（Level 2）→ 分署長（Level 3）逐級推進
  • 核准後系統自動通知下一關；最後一關通過 → 通知申請人
  • 駁回時 原因必填；整張單立即終止，後續關卡不再處理
  • 同一 Step 不能重複簽（防呆）

4.6 行政操作流程 · 常見問題

行政日常

  1. 建立/停用帳號、指派班期
  2. 登錄曠課紀錄 /Admin/AbsenceRecords
  3. 查看彙總報表 /Reports/Admin
  4. 匯出 Excel / CSV /Admin/Export

常見問題 FAQ

Q1：新增學員時「所屬班期」下拉是空的？
A：先至 /Admin/Cohorts 建立班期後再回來新增學員。

Q2：忘記密碼怎麼辦？
A：請行政 / 管理員至 /Admin/Users 使用「重設密碼」功能。

Q3：學員可以自己填曠課嗎？
A：不行。曠課由行政事後登錄，學員僅能查閱。

Q4：Email 收不到通知？
A：這是刻意設計、不是故障。開發環境走 PickupDirectory 模式，郵件會完整寫成 .eml 檔存到 ./mail-pickup/，不連線 SMTP 也就不會真的寄出，以免誤寄給 測試資料裡的真人信箱。切換為實寄的完整步驟見 docs/11-Email通知設定.md。
