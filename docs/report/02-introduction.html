CHAPTER 02

專題簡介

系統想解決什麼？由誰來用？怎麼被實作出來？
本章帶你認識目標、技術架構、六大角色與品質要求。

2.1 系統目標

導入線上請假管理系統，完全取代紙本與 LINE 通報，讓三方在同一平台合作：

🎒 學員
一站式申請、即時查看簽核進度、自動累計請假時數。
👨‍🏫 簽核人
集中處理待辦清單、簽核意見留存、班期累計一目了然。
📋 行政
不再人工抄寫、系統自動匯總、可隨時匯出 CSV / Excel 報表。

2.2 系統架構分層

採 ASP.NET Core MVC 分層架構，各層責任明確、易於測試：

Browser
(瀏覽器)
↔
Controller
(路由 / 驗證)
↔
Service
(商業邏輯)
↔
EF Core
(DbContext)
↔
SQL Server
(資料庫)
層職責代表類別
Controller接請求、模型驗證、呼叫 ServiceLeaveRequestsController、ApprovalsController
Service商業規則、跨表計算、交易控制LeaveCalculator、ApprovalService、LeaveReportService
Entity + DbContext資料模型與 Code First 遷移AppDbContext、LeaveRequest、User…（共 11 個 Entity）

2.3 技術棧

.NET 10
最新 LTS，跨平台執行環境
ASP.NET Core MVC
路由 + Razor 視圖，介面全繁中
EF Core
Code First + Migration，程式碼即為資料庫定義
SQL Server
關聯式資料庫，支援 LocalDB 開發
BCrypt.Net
密碼加鹽雜湊，安全存放
Cookie 認證
HttpOnly、8 小時滑動過期
MailKit
Email 通知（開發用 PickupDirectory）
ClosedXML
Excel 匯出，支援多 sheet
xUnit + FluentAssertions
TDD 規格測試，87/87 全綠

2.4 六大角色與權限

角色英文代號主要權限
學員 🎒Student提交請假申請、查詢自己的紀錄與時數、查閱自己的曠課
導師 👨‍🏫Tutor簽核所屬班期學員的申請（第一關）
科長 👩‍💼SectionChief簽核需二級審核的申請（8.01~24 小時）
分署長 🧑‍⚖️BranchDirector簽核需三級審核的申請（24.01 小時以上）
行政 📋Staff建立帳號、管理班期/假別、登錄曠課、查看與匯出報表
系統管理員 🛡️AdminStaff 全部權限 + 簽核規則管理 + 系統參數調整
CHAPTER 02 · 小結

品質與非功能需求

繁體中文 SQL Server Razor Pages + MVC 可審計 TDD 87/87 全綠

  • 介面全繁體中文，符合本地使用者習慣
  • 所有 public 類別與方法附中文 XML 註解，學習導向
  • 重要操作（登入、簽核、改規則）寫入 AuditLog
  • 採 TDD 開發，服務層先寫測試再實作
