1. 你要蓋的是什麼

一套學生請假管理系統。真實情境是這樣的：某個職訓機構的請假流程， 原本是學員先用 LINE 通知導師、再寫紙本假單、實體傳給導師簽、 導師轉給科長、科長轉給分署長，最後行政人員把資料手動打進 Excel。

整條流程有三種載體、四個關卡，每一環都可能延遲或遺失。你要蓋的系統要解決這件事：

角色系統要幫他做到
學員 線上送出請假申請、隨時查看簽到第幾關、自動累計自己請了幾小時、快到上限時看得到
簽核人
（導師 / 科長 / 分署長）		 一個待辦清單看完所有待簽的單、核准或駁回並留下意見、看得到該學員的累計請假狀況
行政人員 管理帳號 / 班期 / 假別 / 簽核門檻、登錄曠課、彙總報表、匯出 CSV 與 Excel

其中有幾條規則，是這個系統之所以有趣的地方——你在第 11 章會親手把它們寫出來：

  • 時數不等於時段。上課時段是 08:00–12:00 與 13:00–17:00， 午休不計。請 11:00–14:00 只算 2 小時。
  • 簽幾關由時數決定。8 小時內導師決行；8～24 小時要加簽科長； 超過 24 小時還要再加分署長。而且這個門檻是資料表裡的設定，不是寫死在程式裡。
  • 每個班期有請假上限。總上課時數的 10%，超過就送不出去。
想先看成品長什麼樣？ 打開 專題報告的第 03 章， 裡面有系統每一個畫面的實際截圖。看過再回來，你會比較知道自己在往哪裡走。

2. 先認識三個詞

這三個詞會在整本書出現幾百次，先建立粗略印象就好，後面章節會慢慢變清楚。

ASP.NET Core

微軟出的網站開發框架，用 C# 語言寫。 它幫你處理掉「聽網路連線、解析 HTTP 請求、把回應送回去」這些沒人想自己寫的事， 你只要負責「收到這個網址時，該回什麼內容」。

MVC

一種把程式碼分成三堆的組織方式，是為了讓程式碼別全部糊成一團：

字母中文負責什麼
Model模型資料長什麼樣。例如「一張請假單有學員、假別、起訖時間、時數、狀態」。
View檢視畫面長什麼樣。就是那些 HTML。
Controller控制器中間的協調者。收到請求 → 去拿資料 → 決定要給哪個畫面。
為什麼要分三堆？

想像你把「查資料庫」「算請假時數」「產生 HTML」全寫在同一個方法裡。 一開始只有 20 行，很爽。等到規則變複雜、畫面要改版， 你會發現改畫面就有可能弄壞計算邏輯，而且完全沒辦法單獨測試計算對不對。

分開之後，每一塊都只需要理解一件事。這是本書第 9 章的主題， 到時候你會親自把一段業務規則從 Controller 搬出來，體會差別。

Entity Framework Core（EF Core）

讓你用 C# 操作資料庫，而不用自己寫 SQL 的工具。 你寫 db.LeaveRequests.Where(r => r.Status == Approved)， 它翻譯成 SELECT * FROM LeaveRequests WHERE Status = 2 送去資料庫。 第 6 章開始用。

3. 把工具裝好

3.1 .NET SDK（必裝）

SDK 就是「編譯器 + 執行環境 + 命令列工具」的合稱。到 dotnet.microsoft.com/download 下載 .NET 10 SDK（不是 Runtime，要 SDK）。

裝完後，開一個新的終端機視窗（一定要新開，舊的讀不到剛裝好的路徑），輸入：

終端機確認安裝成功
dotnet --version

應該會印出類似 10.0.302 的版本號。看到版本號就成功了。

常見錯誤：'dotnet' 不是內部或外部命令

幾乎都是終端機開太早。安裝程式把 dotnet 加進系統路徑後， 已經開著的終端機不會知道。關掉重開一個，再試一次。

還是不行的話，登出再登入（或重開機）一次。

3.2 編輯器（二選一）

選項適合誰
Visual Studio 2026
Community 版
（免費，Windows）		 新手建議選這個。按 F5 就會編譯、啟動網站、開瀏覽器，一鍵到底。 中斷點除錯的體驗最好——本書很多「動手做」都要你設中斷點看變數， 這在 Visual Studio 裡最直覺。缺點是安裝檔很大（好幾 GB）。 安裝時記得勾選「ASP.NET 與網頁開發」工作負載。
VS Code
（免費，跨平台）		 輕量、開得快。需要另外安裝 C# Dev Kit 擴充套件。 macOS / Linux 使用者選這個。

3.3 資料庫用戶端（建議裝）

你會需要一個工具「用眼睛看資料庫裡到底有什麼」。 Windows 上裝 SQL Server Management Studio（SSMS），免費。 或者用 VS Code 的 SQL Server 擴充套件也可以。

這不是必要的——EF Core 會幫你建表——但當你的資料跟預期不一樣時， 能直接下 SQL 看一眼，比猜半小時有效得多。

4. 資料庫怎麼選

本書用 SQL Server。你有三個選擇，任一個都可以：

選項平台說明
SQL Server
Developer 版		 Windows 免費、功能完整。本書的完成品專案用的就是這個。連線字串是 Server=.;
SQL Server
LocalDB		 Windows 裝 Visual Studio 時會順便裝好，最省事。連線字串是 Server=(localdb)\\MSSQLLocalDB;

6. 給新手的四個心理準備

  1. 看不懂的先記下來，不要停。 很多觀念要到後面幾章才會「啊，原來是為了這個」。 開一個檔案記下你的疑問，每讀完一章回去看，你會發現有些已經自己解開了。
  2. 錯誤訊息是朋友，不是敵人。 紅字不是罵你，是在告訴你哪一行、缺什麼。 把錯誤訊息第一行完整讀完——新手最常見的失誤就是看到紅字就慌，其實答案就寫在上面。
  3. 一天最多兩小時。 這種東西是靠「隔天回來突然懂了」在進步的，不是靠一次坐八小時。
  4. 抄一遍比複製貼上有用。 程式碼區塊有複製按鈕，但前幾章請盡量自己打。 打錯 → 看錯誤訊息 → 修好，這個循環才是真正在學東西。
如果你身邊有 AI 助手 遇到看不懂的地方，可以直接問它「解釋 Program.cs 第 12 行在做什麼」、 「為什麼這裡要用介面」、「我改了 X 然後壞了，這是錯誤訊息：…」。 但先自己讀一遍再問，不然你只是在看別人寫作業。
