# 01 — 需求說明

## 1. 背景

某培訓機構目前以「LINE + 紙本假單」處理學員請假，三方都很辛苦：

| 角色 | 痛點 |
|------|------|
| **學員** | 要 LINE 通知導師、寫紙本假單、等簽核、等行政登記、再對表確認時數，流程冗長 |
| **導師** | LINE 訊息與紙本假單散落各處，同時帶多個班級時容易漏看，無法快速看累計請假狀況 |
| **行政（小華）** | 假單可能遺失、字跡潦草、人工輸入表格費時，每月統計時數心累 |

## 2. 系統目標

導入線上請假管理系統，**完全取代紙本與 LINE 通報**，讓三方在同一平台合作：

| 角色 | 收益 |
|------|------|
| **學員** | 一站式申請、即時查看簽核進度、自動累計請假時數 |
| **導師等簽核人** | 集中處理待辦清單、簽核意見留存、班期累計一目了然 |
| **行政** | 不再人工抄寫，系統自動匯總，可隨時匯出報表 |

## 3. 主要功能

### 3.1 線上請假申請（學員）

- 選擇假別（病假／事假／喪假／公假…，由行政後台維護）
- 以「日期 + 上課時段」下拉選單填寫請假起訖（最小單位 1 小時）
- 填寫請假原因（必填）
- 系統自動計算請假總時數（扣除午休 12:00-13:00 與下班時段 17:00 後）
- 系統自動檢查是否超過班期請假上限（總上課時數 × 上限百分比，預設 10%）

### 3.2 簽核流程管理

- 系統依請假時數自動判斷簽核層級（規則可由 Admin 後台調整）：

  | 請假時數 | 簽核流程 |
  |----------|----------|
  | ≤ 8 小時 | 導師 |
  | 8.01 ~ 24 小時 | 導師 → 科長 |
  | 24.01 小時以上 | 導師 → 科長 → 分署長 |

- **逐級簽核**：上一級未核准前下一級看不到。
- 簽核人可批准或駁回；駁回時必填原因，整張單立即終止。

### 3.3 申請進度追蹤

- 學員可即時查看每張單目前停在第幾關、簽核人是誰、什麼時候簽的
- 可查閱各級簽核意見

### 3.4 請假紀錄查詢

- 學員可查詢個人歷史請假紀錄
- 可依假別或申請狀態篩選
- 可查看各假別累計時數

### 3.5 時數統計管理

- 系統自動統計學員請假時數，行政人員不需再人工記帳
- 行政人員可登錄曠課時數（學員無法自填）
- 報表可依班期、學員、假別、月份匯總

### 3.6 通知（Phase 7 之後）

- 站內通知（簽核人收到代辦、申請人收到結果）
- Email 通知（同上）
- LINE Notify（保留擴充）

## 4. 角色與權限

| 角色 | 主要權限 |
|------|----------|
| **學員** | 提交請假申請、查詢自己的紀錄與時數 |
| **導師** | 簽核所屬班期學員的申請（第一關） |
| **科長** | 簽核需要二級審核的申請 |
| **分署長** | 簽核需要三級審核的申請 |
| **行政** | 建立帳號、管理班期/假別、登錄曠課、查看報表 |
| **系統管理員** | 行政所有權限 + 簽核規則管理 + 系統參數調整 |

## 5. 非功能性需求

- **語言**：介面全繁體中文。
- **資料庫**：SQL Server（搭配 EF Core Code First）。
- **平台**：ASP.NET Core MVC（.NET 10）。
- **可學習性**：本專案為學習導向，所有 public 類別與方法須附中文 XML 註解。
- **可審計**：重要操作（登入、簽核、改規則）寫入 AuditLog。
