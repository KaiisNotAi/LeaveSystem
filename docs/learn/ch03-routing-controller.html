1. 預設路由樣板

回到 Program.cs，看這一段：

C#Program.cs
app.MapControllerRoute(
    name: "default",
    pattern: "{controller=Home}/{action=Index}/{id?}");

那串 pattern 是網址的填空題。 大括號是要填的空格，斜線是分隔。逐段翻譯：

片段意思
{controller=Home} 第一段是 Controller 名稱；沒填就當作 Home
{action=Index} 第二段是 Action（方法）名稱；沒填就當作 Index
{id?} 第三段叫 id，問號代表可有可無

所以：

網址會呼叫哪個方法
/HomeController.Index()（兩個都用預設值）
/HomeHomeController.Index()
/Home/PrivacyHomeController.Privacy()
/LeaveTypes/Edit/5LeaveTypesController.Edit(5)
「Controller」四個字去哪了？

網址寫 /Home，類別卻叫 HomeController—— 框架會自動把 Controller 這個字尾去掉再比對。

這是 MVC 的第一個「約定優於設定」： 只要你照著命名慣例走，就完全不用寫設定檔告訴框架誰對應誰。 代價是你必須知道這些慣例——本章第 6 節會整理。

2. 動手：第一個自己的 Controller

我們來做「假別清單」的雛形。假別（病假、事假…）是這個系統最單純的資料， 第 7 章會把它做成完整的 CRUD，現在先用寫死的資料把路由跑通。

在 Controllers 資料夾新增 LeaveTypesController.cs：

新增檔案Controllers/LeaveTypesController.cs
using Microsoft.AspNetCore.Mvc;

namespace MyLeaveSystem.Controllers;

// 1. 類別名稱一定要用 Controller 結尾
// 2. 一定要繼承 Controller（那個冒號的意思）
public class LeaveTypesController : Controller
{
    // GET /LeaveTypes  或  /LeaveTypes/Index
    public IActionResult Index()
    {
        return Content("這裡以後要顯示假別清單");
    }
}

存檔、重新啟動（Ctrl+C 然後 dotnet run， 或直接用 dotnet watch run），開 /LeaveTypes。 應該會看到那行純文字。

出現 404 找不到頁面？

依序檢查這四件事，九成是其中之一：

  1. 類別名稱是不是 LeaveTypesController（Controller 結尾，大小寫也要對）
  2. 有沒有 : Controller
  3. 方法是不是 public（private 的方法路由找不到）
  4. C# 改了要重新編譯——只存檔重新整理是不夠的

2.1 加第二個 Action

修改Controllers/LeaveTypesController.cs
public class LeaveTypesController : Controller
{
    public IActionResult Index()
    {
        return Content("這裡以後要顯示假別清單");
    }

    // GET /LeaveTypes/About
    public IActionResult About()
    {
        return Content("假別用來分類請假原因：病假、事假、喪假、公假。");
    }
}

開 /LeaveTypes/About。你不需要做任何註冊——加一個 public 方法，路由就自己認得了。

3. 網址參數怎麼傳進來

樣板最後那個 {id?} 現在派上用場。加一個 Details：

修改Controllers/LeaveTypesController.cs
// GET /LeaveTypes/Details/3
public IActionResult Details(int id)
{
    return Content($"你要看第 {id} 號假別");
}

開 /LeaveTypes/Details/3，會看到「你要看第 3 號假別」。

框架怎麼知道要把 3 塞進 id？

因為參數名稱 id 跟路由樣板裡的 {id?} 同名。 這叫「模型繫結（Model Binding）」，第 5 章會完整講。

如果你把參數改名成 typeId，路由就對不上了， typeId 會拿到 0（int 的預設值）。試試看，親眼看到比較有印象。

3.1 查詢字串參數

網址問號後面的東西，也會自動對應到同名參數：

修改Controllers/LeaveTypesController.cs
// GET /LeaveTypes/Search?keyword=病&onlyActive=true
public IActionResult Search(string? keyword, bool onlyActive)
{
    return Content($"關鍵字={keyword}，只看啟用={onlyActive}");
}

開 /LeaveTypes/Search?keyword=病&onlyActive=true。 不帶參數直接開 /LeaveTypes/Search 也可以—— keyword 會是 null，onlyActive 會是 false。

危險：不要相信網址上的任何東西

使用者可以手動把網址改成任何值。 /LeaveTypes/Details/999999、/Approvals/Details/{別人的單號}—— 全都能打得出來。

所以每一個吃 id 的 Action 都要問自己：「這個人有資格看這筆資料嗎？」 第 10 章與第 11 章會反覆處理這件事。這是新手最容易漏掉、也最嚴重的安全問題。

4. IActionResult：可以回傳什麼

到目前為止我們都回傳 Content(...)，那只是純文字。 IActionResult 是「一個 HTTP 回應」的抽象，實際可以是很多種東西：

C#常見的回傳方式
return View();                          // 找對應的 .cshtml 畫面 → 第 4 章
return View(model);                     // 同上，並把資料帶過去

return Content("純文字");               // 直接回一串字
return Json(new { ok = true });          // 回 JSON（給前端 JS 用）

return RedirectToAction("Index");       // 叫瀏覽器轉去別的 Action
return Redirect("/LeaveTypes");         // 轉去某個網址

return NotFound();                      // 404
return Forbid();                        // 403，已登入但沒權限
return Challenge();                     // 導去登入頁

return File(bytes, "text/csv", "a.csv"); // 下載檔案 → 第 12 章

4.1 動手：查不到就回 404

把 Details 改成比較像真的：

修改Controllers/LeaveTypesController.cs
public IActionResult Details(int id)
{
    // 暫時用寫死的資料，第 6 章會換成真的資料庫
    var names = new Dictionary<int, string>
    {
        [1] = "病假", [2] = "事假", [3] = "喪假", [4] = "公假"
    };

    if (!names.ContainsKey(id))
    {
        return NotFound();      // 回 404
    }

    return Content($"第 {id} 號假別是「{names[id]}」");
}

試 /LeaveTypes/Details/2（正常）與 /LeaveTypes/Details/99（404）。

為什麼回傳型別要寫 IActionResult，不寫 ContentResult？ 因為同一個方法在不同情況下要回不同種類的結果—— 正常時回內容、找不到時回 404。IActionResult 是它們共同的介面 （還記得第 1 章第 7 節嗎）， 所以兩種都能用同一個 return 回出去。

5. 屬性路由：不想照樣板走的時候

預設樣板夠用九成場合。但有時你想要一個不照規則的網址， 這時可以直接在方法上標屬性（Attribute）：

C#屬性路由的例子
// 這個 Action 的網址變成 /leave-types/all，而不是 /LeaveTypes/AllTypes
[Route("leave-types/all")]
public IActionResult AllTypes()
{
    return Content("全部假別");
}

也可以掛在整個類別上。完成品專案就用了這招——因為它有兩個同名的 AbsenceRecordsController（一個給學員、一個給行政）， 必須用路由把它們分開：

C#取自完成品：Controllers/Admin/AbsenceRecordsController.cs:20
[Route("Admin/AbsenceRecords/{action=Index}/{id?}")]
[Authorize(Roles = "Admin,Staff")]
public class AbsenceRecordsController : Controller
屬性是什麼？ 方括號裡那些 [Route(...)]、[Authorize(...)]、[HttpPost] 叫做「屬性」，是貼在程式碼上的標籤。 它們不會執行任何邏輯，只是讓框架讀到之後改變行為。 你在本書後面會看到很多種。

6. MVC 的三個「約定」

本章出現的所有「魔法」，其實都是這三條約定。把它們記起來，之後就不會覺得莫名其妙：

#約定例子
1 Controller 類別名稱要以 Controller 結尾， 比對網址時會去掉這個字尾 LeaveTypesController → 網址 /LeaveTypes
2 public 方法自動成為 Action，方法名就是網址第二段 public IActionResult About() → /LeaveTypes/About
3 return View() 會去找 Views/{Controller 名}/{Action 名}.cshtml LeaveTypesController.Index() → Views/LeaveTypes/Index.cshtml

第 3 條你還沒用到——那是下一章的主題。

約定的代價

約定讓你少寫很多設定，但也代表改個檔名就可能悄悄壞掉， 而且編譯器不會警告你。

例如把 Views/LeaveTypes/ 資料夾改名成 Views/LeaveType/（少個 s）， 編譯完全正常，但一開頁面就會跳 InvalidOperationException: The view 'Index' was not found. ——訊息裡會列出它找過哪些路徑，仔細讀那個清單就知道哪裡不對。

7. 一個現在就要養成的習慣：Controller 要「薄」

你剛才在 Details 裡塞了一個 Dictionary。現在無所謂， 但請記住這個原則：

Controller 只做三件事

① 收——接住請求參數。
② 轉——交給別人（第 6 章的資料庫、第 9 章的 Service）處理。
③ 給——決定回哪個畫面或轉去哪裡。

「算」不是 Controller 的工作。 請假時數怎麼算、能不能簽這一關、超過上限沒——這些都不該寫在這裡。 第 9 章你會把它們搬出去，並體會為什麼。
